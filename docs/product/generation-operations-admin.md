# 生成运营后台与账户体系范围

状态：当前版本已确认
确认日期：2026-11-18

## 1. 目标

在现有图片与视频生成能力之上，补齐真实用户账户、创作资源归属和独立生成运营后台。后台帮助内部人员回答三类问题：系统每天生成了多少任务、任务为什么失败或变慢、不同供应商和模型产生了多少成本。

当前版本不改变画布作为用户制作品台的定位，也不另建一套用户生成工作台。

## 2. 当前基础

项目已经具备：

- 画布中的图片和视频生成节点；
- 图片、视频和音频参考素材上传及画布连线；
- 持久化异步生成任务；
- 本地任务队列和按平台连接控制的并发名额；
- 任务恢复、超时、状态不明确保护；
- SSE 状态通知和轮询降级；
- 供应商结果转存 OSS，保存失败可单独重试。

当前缺口是：应用仍使用固定本地身份，项目、任务和大部分素材没有真实用户归属；没有独立运营后台；RunningHub 的任务级用量尚未落库；生产指标、成本汇总和管理员审计尚未形成产品能力。

## 3. 本版本范围

### 3.1 用户账户与资源归属

- 个人用户账户，不建设组织和团队；
- 邮箱注册、邮箱验证、密码登录和找回密码；
- Go API 负责账户登录、凭据验证、MFA 和短期 JWT 签发；
- Go API 使用稳定的本地用户 ID 归属创作资源；
- 首版只有 `user` 和 `admin` 两种角色；
- 管理员强制 MFA，敏感操作要求近期重新验证；
- 用户禁用后立即撤销会话并禁止新生成；
- 项目、文件夹、上传素材、生成任务、生成结果、角色和个人技能必须归属资源所有者；
- 所有资源授权由 API 校验，不能只依靠前端隐藏入口；
- 历史无归属资源通过受保护的一次性流程迁移给初始所有者账户，并保留原项目、节点和任务标识。

### 3.2 独立生成运营后台

后台位于独立的 `apps/admin`，用户制作品台继续位于 `apps/web`。两者调用同一套 Go API，后台不直接访问或修改业务数据库。

首版模块：

1. **总览**：任务量、成功率、阶段耗时、队列状态和供应商成本；
2. **任务**：查询任务、查看状态时间线、错误、供应商任务 ID 和结果保存状态；
3. **成本**：供应商用量、预计成本、实际成本、已对账成本、失败成本和成本调整；
4. **用户**：账户状态、资源归属和禁用操作；
5. **审计记录**：管理员登录、敏感内容访问、任务操作和用户状态变更。

首版管理员可以：

- 继续查询原供应商任务；
- 重试保存已有供应商结果；
- 取消尚未提交供应商的排队任务；
- 禁用异常用户。

首版管理员不可以：

- 未经用户重新确认而提交新的付费生成；
- 修改任务原始输入后沿用旧任务；
- 删除成本、任务事件或审计记录；
- 直接把失败任务改成成功。

### 3.3 任务事件与生产指标

任务保留当前状态，同时追加不可覆盖的任务事件：

- 任务创建；
- 进入队列；
- 开始提交；
- 供应商接受；
- 供应商生成成功、失败或内容审核拒绝；
- 开始保存；
- 交付成功或保存失败；
- 管理员处理。

生产监控分别计算：

- 排队耗时：任务创建到开始提交；
- 供应商耗时：供应商接受到返回结果；
- 保存耗时：取得结果到 OSS 保存完成；
- 端到端耗时：任务创建到结果可访问。

后台展示平均值、P50、P90 和 P95，并支持按图片/视频、模型、供应商、状态、用户、项目和时间范围筛选。数据以 UTC 存储，按管理员选择的时区展示；总览和队列状态以一分钟内更新为首版目标。

成功口径分为：

- **供应商成功**：供应商已经返回结果；
- **交付成功**：结果已保存并可由用户访问；
- **用户采用**：用户确认、下载、连接至下游节点或加入后续制作流程。

仅预览、打开项目或结果自动回填不算用户采用。

### 3.4 供应商用量与成本

成本能力只服务内部运营，不向用户计费。

每个任务保存：

- 供应商、模型和模型版本；
- 原始计量单位及原始币种；
- 供应商返回的原始用量；
- 预计供应商成本；
- 实际供应商成本；
- 已对账供应商成本；
- 成本调整和调整原因；
- 成本数据的来源、状态和采集时间。

RunningHub 任务结果接口已经提供 `consumeCoins`、`consumeMoney`、`thirdPartyConsumeMoney`、`settleMode`、`chargedPoint` 和 `taskCostTime` 等字段。首版完整保存原始字段；在真实账号响应验证字段语义前，不凭字段名称编造换算关系。实时任务级用量用于成本采集，RunningHub 控制台账单导出用于后续对账。

字节官方生图按模型、规格和实际计费数量计算预计及实际成本，再通过官方账单确认。供应商成本缺失时标记为待确认并告警，不伪造为零。

供应商已经产生用量但结果未成功交付时，成本计入失败成本，并与成功任务成本分开展示。

### 3.5 告警与排障

首版告警：

- 队列中最老任务等待时间超过阈值；
- Worker 心跳中断；
- 模型或供应商失败率超过阈值；
- 供应商成功但结果保存失败；
- 单日成本或单任务成本超过阈值；
- 供应商实际用量缺失。

同一问题使用一个持续告警，支持未处理、已确认、已恢复状态，以及分组、冷却时间、严重程度、首次/最近发生时间和管理员处理记录。第一版在管理后台展示并接入现有错误监控；邮件、Slack 和短信通知不在本次范围。

### 3.6 最低安全闭环

公开注册前必须具备：

- 用户和 IP 双层请求限制；
- 可配置的单用户并发、单模型并发和每日用量限制；
- 可疑注册、登录、找回密码和生成行为触发 CAPTCHA；
- Prompt 基础规则检查和供应商内容审核；
- 内容审核拒绝单独分类并计入用户风险记录；
- 用户接受当前服务条款与内容规则版本后才能生成；
- 管理员能够禁用异常用户。

首版不自建图片/视频审核模型，不建设举报、申诉或人工审核队列。

后台任务列表默认只展示元数据。管理员明确打开完整 Prompt 或素材时记录访问审计；素材使用短时访问地址，日志和错误信息必须脱敏，任何界面都不展示供应商密钥。

## 4. 明确不做

以下能力不属于当前版本，也不列为既定后续方向：

- 平台积分；
- 用户余额与扣费；
- 生成前报价；
- 产品价格表和目标毛利定价；
- 注册赠送积分；
- 支付、充值、套餐、优惠码、退款和发票；
- 以积分推导的名义收入或毛利报表。

如未来重新考虑商业化结算方式，应从新的产品决策开始，不继承已被 ADR-0018 取代的积分方案。

## 5. 数据与架构边界

- 生产目标数据库为 PostgreSQL，使用受审查的 Goose SQL 迁移；
- 各领域只允许一个权威写入者，不允许 Go 与 TypeScript 无协议双写；
- 账户和资源归属按完整领域边界迁移；
- 生成任务迁移必须保留批准、幂等、租约隔离、供应商任务 ID 和结果保存语义；
- 管理后台只通过 API 操作；
- 任务指标来自权威任务事件，成本指标来自成本记录；
- Sentry、Langfuse 和普通日志只作诊断，不作为任务或成本账的权威来源。

迁移采用停写窗口：停止新写入和新生成提交，备份 SQLite 与对象存储清单，创建初始所有者，导入并校验标识与关系，切换流量，并在明确窗口内保留回滚能力。已经取得供应商任务 ID 的任务只恢复查询，绝不因迁移重新提交。

## 6. 数据保留

- 供应商用量、成本对账、成本调整、任务核心记录和任务事件长期保留；
- 脱敏后的供应商原始响应及诊断日志默认保留 90 天；
- 聚合生产指标长期保留；
- Prompt、上传素材和生成结果跟随用户项目及账户删除策略；
- 账户删除后保留必要运营与审计字段，并去除非必要个人内容。

## 7. 实施顺序

1. PostgreSQL 账户、认证、本地用户 ID、管理员 MFA 和资源归属；
2. 历史数据迁移与资源隔离；
3. 生成任务事件、RunningHub 用量和字节成本采集；
4. `apps/admin` 的只读总览、任务与成本页面；
5. 安全的任务排障操作、用户禁用和审计记录；
6. 告警、限流、CAPTCHA 和最低内容安全；
7. 备份恢复演练、迁移回滚演练和公开注册验收。

## 8. 上线验收

上线前必须验证：

- 普通用户无法访问其他用户的项目、素材、任务或结果；
- 普通用户无法进入管理后台；
- 管理员敏感操作要求 MFA 并留下审计；
- 禁用账户立即撤销会话并阻止新生成；
- 相同请求 ID 并发提交仍只创建一个生成任务；
- 迁移保留项目、节点、任务、媒体关联和供应商任务 ID；
- 迁移或恢复不会重新提交已经付费的供应商任务；
- 四段任务耗时可以从任务事件稳定重建；
- RunningHub 原始用量能够按任务查询并汇总；
- 字节成本规则和账单对账能够解释差异；
- 失败成本与成功任务成本分开统计；
- PostgreSQL 备份、时间点恢复和恢复后关系校验通过；
- 公开注册前，限流、CAPTCHA、规则接受和内容审核拒绝链路可用。
