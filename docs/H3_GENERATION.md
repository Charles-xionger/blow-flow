# H3 多模态参考生视频

`runninghub-h3` 使用工作流 `2116745173157138433`，与 Krea2 共用 RunningHub 平台连接和持久化任务服务。前端入口为现有“图生视频”节点，选择 H3 后使用参考素材面板。旧视频模型继续使用原接口。

## 工作流与输入

仓库模板 `config/workflows/h3.json` 来自用户确认的桌面文件 `H3无损融合单采【官方满血API画布级本地流】_api (1).json`。模板包含六个已连接图片输入、一个视频加载器、三个音频加载器；H3 节点动态输入支持九图、三视频及三独立音频。实现按每次请求扩展加载节点，移除未使用的参考连接，并仅保留输出节点 148 的依赖。不会以示例图片、空视频或 `None` 音频补足输入。

- 提示词：238.value；后端随机种子：129.noise_seed。
- 时长：227.value；224 将帧数向上对齐到 `17k+5`，输出 24fps。首版目标时长 5–15 整数秒，默认 7 秒，对应预计 175/24 ≈ 7.29 秒；不裁剪生成结果。此范围选择了模型文档中的常用训练范围，未将 schema 的 3600 帧上限当作可靠长视频能力。
- 生成尺寸：直接赋给 136.width/height，不使用 228 的百万像素换算；其余生成、权重及采样配置沿用模板。档位以短边 480/720/1080 为目标，结合画幅后各边按 JavaScript `Math.round(edge/32)*32` 对齐，界面显示实际值。16:9 分别为 864×480、1280×736、1920×1088。这是实际采样尺寸，不是生成后缩小。
- 输出：148 的 H.264 MP4，保留 121 解码出的原生生成音频。

图片、视频可从画布节点连入；三类参考素材也可直接上传。面板支持排序、移除和点击标签插入提示词。角色节点使用第一张角色参考图，其他图片可分别连入或上传。所有来源合并后按明确顺序提交，超过九图／三视频／三音频时拒绝生成，不静默丢弃。

参考视频默认使用原声，可逐段关闭；上传时检测到无音轨的视频关闭此选项。已有画布视频若实际无音轨而开启原声，后台在生成前明确拒绝，要求关闭原声，避免悄悄改变音频编号。视频的声音按视频顺序先占用 `<Audio N>`，独立音频随后编号。调整素材顺序或原声后，面板提醒检查提示词编号。

## 上传与素材校验

新增 `POST /api/upload/reference` 接受一个 multipart `file`，先校验本地字节，再以唯一文件名保存到现有 OSS 的 `references/`。图片为 JPG/PNG/WEBP，视频为 MP4/AVI/MOV/MKV，音频为 MP3/WAV/FLAC，单文件限制 30 MiB。实际可解码内容由 ffprobe 检查，不能只改扩展名伪装格式。

视频参考允许约 0.21–15 秒（15.1 秒容纳原生帧数对齐），更长素材需先选取片段；当前不提供剪辑器。`VHS_LoadVideo.force_rate=24` 统一参考帧率，加载帧数不超过本次生成帧数，并按素材时长向下对齐到 `17k+5`；配对原声使用同一加载器的时长截取，避免画面向下对齐而声音仍多出一段。独立音频不编造未核实的时长上限，仍受文件体积和解码约束。浏览器能否预览 AVI/MKV 取决于浏览器编解码器，后台校验和平台加载独立进行。

任务输入只接受本项目 OSS 的无签名公网 URL；任意第三方地址、内网地址和重定向不交给后台下载。旧画布引用第三方地址时，应先下载后通过参考素材入口上传。项目的持久化输入 URL 与 RunningHub 临时文件名分开保存；平台密钥仅用于后台 multipart 上传及任务请求。

## 任务生命周期

继续使用 `/api/generation/models`、`/api/generation/tasks`、任务 SSE 和现有 worker。输入增加 `duration` 和有序 `references`：

```json
{
  "requestId": "独立请求标识",
  "modelId": "runninghub-h3",
  "canvasId": "项目标识",
  "nodeId": "视频节点标识",
  "input": {
    "prompt": "参考 <Picture 1> 的人物和 <Video 1> 的动作",
    "width": 1280,
    "height": 736,
    "duration": 7,
    "references": [
      { "kind": "image", "url": "https://你的Bucket.oss-cn-hangzhou.aliyuncs.com/references/image.png" },
      { "kind": "video", "url": "https://你的Bucket.oss-cn-hangzhou.aliyuncs.com/references/video.mp4", "useAudio": false }
    ]
  }
}
```

可选 `input.instanceType: "plus"` 选择 RunningHub 高性能 48G（RTX 4090 48G）实例，作为创建请求的顶层字段发送；省略即平台标准 24G 实例，其他值在入队前拒绝。该字段随任务输入持久化，恢复和接管都沿用创建时的选择。面板中 ⚡ 按钮按节点保存此选择，默认关闭；1080p 且未开启时提示可能显存不足。高性能实例按平台价格计费，账号需有对应权限。平台返回 `torch.OutOfMemoryError` 时任务显示“显存不足”并提示降低分辨率、时长或选择高性能渠道。参数依据 RunningHub 官方 [ComfyUI_RH_APICall](https://github.com/HM-RunningHub/ComfyUI_RH_APICall) 插件的 `create_task`。

worker 下载并校验素材，再上传 RunningHub 取得 `fileName`，构建完整图后提交一次。任务增加持久化的提交边界标记：素材准备阶段退出可重新准备，删除节点会取消该阶段的任务；即将调用生成接口前持久化标记，之后响应不明仍进入待核实且不自动重提。每段网络操作有超时，素材准备续租，旧进程被接管后不能继续提交。

素材传输使用独立预算：OSS 下载 60 秒、平台上传 180 秒；不复用创建／查询接口默认的 30 秒超时。准备租约覆盖最长传输预算并保留 45 秒余量，在下载与上传前续租。准备失败时显示下载、校验或上传阶段；私有诊断仅记录阶段、素材序号／类型、超时原因及 HTTP／平台错误码，不保存原始异常或鉴权信息。此修正来自真实约 20 MB 参考图上传在 30 秒处超时的复现，延长预算不保证网络故障时上传成功。

视频任务公开响应包含 `outputType: "video"`，恢复写入 `videoSrc`，不写入 `imageSrc`。产物以 `video/mp4` 保存至 `videos/generation/<taskId>/<index>.mp4`。转存失败重试原结果，已上传但未记录的 MP4 可通过 HEAD 找回；生成阶段不会因转存失败重复执行。

## 运行

沿用 [Krea2 部署说明](KREA2_GENERATION.md) 中的 RunningHub、OSS 与数据库配置，同时运行 Web 和 `pnpm generation:worker`。两个进程都需要安装 **ffprobe**；它通常随 FFmpeg 一起提供。非 PATH 安装可设置 `FFPROBE_PATH` 为可执行文件绝对路径。缺失时上传或素材准备给出明确错误，不提交生成。

如果使用 `GENERATION_CONFIG_PATH` 自定义目录，需要将默认配置中的 H3 模型加入管理员文件；默认目录的新增模型不会覆盖外部文件。H3 使用与 Krea2 相同的连接 ID，默认共享一个生成并发名额。

若原始大图上传持续超时，可使用 [可选的平台网络选路](KREA2_GENERATION.md#可选的平台网络选路)。本机约 20 MB 素材在香港节点直连约 3 秒完成，而此前解析到的另一节点在 60 秒内只传出约 1 MB；仅延长上传预算不能替代正确选路。
