# 使用 SSE 同步生成任务的最新状态

生成任务通知首版面向单机部署，Web 与 worker 独立进程共享现有 SQLite，不引入 Redis；范围为任务状态和最终图片，不包含多人协作、生成百分比或预览图。浏览器使用 `@microsoft/fetch-event-source` 接收 SSE，每个画布页面共用一条连接，生成与重试等操作继续通过 HTTP 提交。

数据库继续作为任务状态的依据，首次连接和断线重连同步最新状态，不要求逐条回放中间状态；这延续 ADR 0002 的后台执行与恢复语义。正常网络下以状态持久化后 1 秒内通知在线页面为目标；SSE 持续不可用时降级为每 10 秒轮询并显示连接提示，恢复推送后停止轮询，避免漏掉最终结果。

首版采用最小跨进程方案：Web 进程每 500ms 批量检查当前订阅的任务，仅在公开状态或结果变化时推送；同一进程的连接共享检查器，无订阅时停止检查。这保留了服务端数据库定时检查，以降低进程间通知丢失及恢复的实现成本。

RunningHub 侧在本次接入 WebSocket，采用 WebSocket 优先、HTTP 查询兜底：由 worker 连接平台返回的 `netWssUrl`，排队尚未取得地址、连接失败、断线、worker 重启或完成事件缺失时，使用原平台任务 ID 查询并恢复跟踪，不重新提交生成任务。完成通知用于触发 HTTP 结果查询，经确认后持久化状态并按现有流程转存 OSS；平台鉴权地址仅限后端使用，不通过 SSE 暴露。平台实际完成到本地落库的等待不计入上述 1 秒通知目标。

[RunningHub 官方进度示例](https://www.runninghub.ai/runninghub-api-doc-en/doc-8287471) 展示了通过 outputs 接口取得运行中任务的 WebSocket 地址，以及收到完成信号后查询产物的方式。示例未构成消息可靠投递或地址长期有效的保证；接入需保留查询恢复路径，并验证当前国际站工作流的实际事件与连接行为。
