# 模型统一表达生成能力，平台差异由后端封装

产品的模型目录同时容纳厂商模型和封装好的生成工作流，前端使用统一的模型选择与生成操作；后端保留接入类型及各自的参数映射，避免业务界面依赖平台协议。平台连接由管理员统一配置并供模型引用，首版使用者选择模型而不各自配置平台凭据。

首批以两个 RunningHub 工作流可用为交付范围，不以 Gemini 或第二个平台的真实接入为前置条件；跨平台扩展能力仍需在后续接入其他平台时验证。允许前端补充由模型能力驱动的通用输入及任务状态展示，平台专属调用逻辑留在后端。首版通过后端配置文件登记工作流及参数映射，可视化导入和映射编辑器留待后续评估。

首批仅新增 RunningHub 模型使用新中间层；已有模型保持原调用行为，现有文本调用本次不迁移。模型层为文本、图片与视频保留能力分类，实际文本接入及跨平台兼容性在后续迁移中验证。

视频先以一张参考图验证，不将现有工作流连接三张图片的配置固化为产品要求。首批图片采用用户的 Krea2 工作流，视频采用用户修正后的 H3 工作流；官方 MiniMax H3 标准 API 留作后续选项。此选择取代此前优先官方 API 的决定，因为用户要求实际低分辨率生成，而当前官方注册表只声明 2K。多参考图在前端编号并允许调整顺序，后端按确定顺序提交。

尺寸、时长、提示词与参考图按具体能力开放，不固定为当前导出的值；允许值仍须来自真实接入契约或经核实的节点定义。视频提供 480p、720p、1080p 的实际生成档位，以修正后的工作流支持及验证为前提；不以 2K 生成后缩小文件代替该要求。前端将分辨率档位与画幅分开选择，后台按工作流要求对齐像素，并在前端显示实际生成尺寸；具体换算规则在核实修正后的工作流后确定。种子不在前端展示，对支持种子的接入在后端生成并记录实际提交值，不对未声明种子参数的 API 编造字段。
