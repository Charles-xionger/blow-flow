# 02: 画布结构操作的批次撤销

**What to build:** 用户可以把一次节点、连线或结构操作整体撤销和重做，相关节点、连线、提示词引用与布局同步恢复。复用已有持久历史，不另建第二套撤销栈。当前票完成普通节点的结构操作，生成任务副作用由第 03 票收口。

**Blocked by:** 01: 持久历史基础与基础编辑撤销

**Status:** ready-for-agent

- [x] 节点创建、删除和批量删除均进入统一历史；一次批量操作形成一个撤销批次，内部变更仍可追溯。
- [x] 创建连线、断开连线与上游排序可撤销；恢复时继续满足连线类型、引用顺序与无环等现有规则。
- [x] 删除节点或断开连线引起的提示词节点引用转普通文本，与结构变化进入同一批次；撤销恢复结构和原分段内容，不能只恢复连线。
- [x] 分组和取消分组可整体撤销，恢复父子关系、位置与尺寸；组内拖动不会破坏全局位置。
- [x] 复制与导入可整体撤销、重做；redo 复用已保存节点身份和内容，不重新分配 ID 或重新读取导入文件。
- [x] 复制和导入继续遵循现有节点引用重映射及生成任务关联清理规则，不因历史恢复给副本挂上原节点任务。
- [x] 非法连接或失败操作不产生半完成批次，不留下孤立连线和重复节点；无变化操作不消耗撤销步骤。
- [x] 刷新后能撤销、重做上述批次，新编辑仍按既定规则使 redo 分支失效。
- [x] 在第 03 票完成前，涉及生成任务的操作继续遵循既有取消与恢复约束，不通过直接恢复快照绕过任务删除状态。
- [x] 验证带引用节点删除、多选批量操作、组内布局、复制重映射、导入后刷新与反复 undo/redo，确保没有状态漂移。
- [x] 范围仅为现有画布操作；不增加 Agent、MCP 或人工冲突裁决。


## Comments

2026-11-03：完成普通节点与连线的批次历史。创建、批量关联创建、删除（包含子树）、断线及引用转文本、上游排序、分组/取消分组、复制和导入共用持久历史入口。React Flow 键盘删除先合并节点和连线再发布一次变更。嵌套分组只移动选中根节点，取消分组保留祖先坐标，反复回放不漂移。

导入延续现有行为：先保存原项目，再建立独立项目；导入内容和项目名形成一步，新项目内撤销回到空画布，redo 使用保存的身份，不重新读文件。首次保存前撤销为空画布仍持久化 redo 分支。非法结构在发布前拒绝；旧导出中缺失端点的连线仍移除，并把相应提示词引用转为文本。

模型切换导致输入类型不兼容时，模型、失效连线及提示词引用在同一步内更新和恢复。涉及生成任务身份的删除沿用第 01 票的历史边界与取消保护；回放检查本地删除标记，不恢复已取消任务。完整任务撤销语义按本票约定留给第 03 票。
