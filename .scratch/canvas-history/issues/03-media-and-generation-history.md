# 03: 素材与现有生成任务的撤销协调

**What to build:** 用户撤销素材引用修改或带生成任务节点的删除时，可以恢复内容，同时保留正确的生成任务状态。历史不重复复制大文件，undo/redo 不重新提交生成，迟到结果不复活已删除节点。本票针对已有图片与视频生成任务，不依赖未来 Agent。

**Blocked by:** 02: 画布结构操作的批次撤销

**Status:** ready-for-agent

- [ ] 上传后挂接素材、替换、移除、排序与已有素材相关设置可撤销、重做；恢复的是已保存内容与引用，不重新上传或生成。
- [ ] 历史使用可持久解析的原始素材引用，不依赖预览缓存、临时 Blob URL 或平台临时下载链接；不在每一步历史中复制二进制内容。
- [ ] 已有导入或历史内容中的内嵌媒体有明确兼容处理，升级后可显示并恢复，不静默丢失素材。
- [ ] 首版不自动裁剪用户历史；应用不得删除仍被保留历史引用的原始素材。缺失原始文件时明确提示，节点其余内容仍可恢复，不以预览图冒充原素材。
- [ ] 删除节点时，未提交生成按现有规则取消，已提交生成继续跟踪并保存结果；撤销删除不重新提交已取消任务。
- [ ] 恢复节点正确协调本地待发送删除请求、服务端删除状态与生成任务关联，避免界面恢复但后台仍错误处理节点身份。
- [ ] 已提交任务迟到结果不得复活已删除节点，不覆盖已经改变的内容或更新任务的展示；保留可追溯结果，复用现有任务查看与恢复行为，不新增人工冲突裁决。
- [ ] redo 重新应用已保存内容，不重新执行付费请求；生成进度、轮询和转存状态不会占满内容撤销栈，也不会因恢复旧内容而倒退任务事实。
- [ ] 失败、取消、待核实、转存失败等状态遵循现有生成任务规则；恢复或重试保存不能变相创建新生成。
- [ ] 验证删除排队任务后撤销、删除运行任务后结果迟到、断网删除后撤销、素材替换与刷新恢复，以及重复 redo 不增加平台提交次数；使用受控生成适配验证，无需真实付费调用。
- [ ] 不改变项目回收站和永久删除的既定行为，不实现 Agent、MCP 或人工覆盖确认流程。
