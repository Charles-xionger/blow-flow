# 01: 持久历史基础与基础编辑撤销

**What to build:** 用户可以撤销、重做节点移动、尺寸调整、标题、提示词和参数编辑，刷新或重新打开项目后继续使用历史。建立统一画布操作入口与持久历史，以当前项目内容作为起点，不推测旧操作。先以完整编辑链路验证成熟差异工具的适用性；Immer 正逆补丁是候选，不是必须采用的既定方案。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 已有项目首次启用历史时建立初始检查点，重复打开不会重置历史；没有历史的项目正常显示不可撤销状态。
- [x] 节点移动、尺寸调整、标题、提示词及生成参数修改均经过统一操作入口；一次拖动或尺寸调整只产生一步，选中、缩放、测量和任务进度不进入内容历史。
- [x] 连续文字编辑按明确的编辑边界合并；文字编辑器获得焦点时，其撤销与画布历史交接一致，失焦后不会对同一修改重复撤销。
- [x] 提供撤销与重做入口及快捷键，正确显示可用状态；redo 应用已保存的变更，不重新调用业务生成逻辑。
- [x] 当前内容、历史位置及操作提交结果一致持久化；重复提交同一操作不会新增历史或重复修改，恢复不会使保存版本倒退。
- [x] 刷新、关闭后重开可恢复内容与 undo/redo 位置；项目切换不串用历史。
- [x] undo 后产生新的有效内容编辑会清空当前 redo 分支，但保留此前记录；无变化操作不创建历史或破坏 redo。
- [x] 在后续票尚未覆盖所有修改入口期间，未迁移操作也不能让旧历史静默覆盖新内容；采用明确的过渡处理，最终由后续票完成迁移。
- [x] 保留现有保存版本检查、失败提示与本地内容保护，不增加覆盖远端内容的隐式重试；断网或保存失败不能显示为已服务端保存。
- [x] 验证拖动合并、文字交接、redo 分支失效、重复请求、刷新恢复与项目隔离。优先通过公开操作入口及真实持久层测试，不仅测试补丁库本身。
- [x] 不实现 Agent、MCP、Agent 步骤状态、人工冲突裁决或 Skill；不引入未经验证的多人协作数据模型。
