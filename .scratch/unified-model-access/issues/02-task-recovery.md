# 02: 任务恢复与画布状态一致性

**What to build:** 创作者刷新或重新打开画布后可以接回生成任务，服务重启后继续查询原任务；等待超时可继续查询。重新生成和删除节点时，旧任务不会覆盖新结果或重建节点。

**Blocked by:** 01 — 接通 Krea2 生图与可靠提交。

**Status:** ready-for-agent

## Context

依据父规格“统一模型层与平台中间层：RunningHub 生图首版”与 ADR 0001、0002。01 已提供统一任务接口、持久化记录、请求幂等、连接队列、平台提交与基础结果保存。本票沿用这些契约，不创建另一套任务系统。用户已确认统一任务接口、真实临时数据库及模拟外部服务的测试边界。

生成任务与画布展示分开：每次生成有独立输入快照，节点只展示最近一次任务；切换画布或卸载组件不等同于删除。恢复意味着查询原任务，绝不以重新提交代替。

## Acceptance criteria

- [ ] 刷新页面或重新打开已保存画布可恢复本地任务关联和状态，不停留在无法恢复的“生成中”布尔值。
- [ ] 创建响应丢失后，客户端通过原请求标识找到已有任务，不创建新的平台任务；关联数据足以恢复尚未收到创建响应的请求。
- [ ] 后台服务重启后，已保存平台任务 ID 的任务继续查询原 ID；本地排队任务按正常队列继续执行。
- [ ] 提交阶段崩溃且无法确认是否已被平台接收时进入待核实并保留并发占位，不恢复为可重新提交的排队状态。
- [ ] 任务过了配置化查询期限后停止自动轮询，界面显示等待超时；用户可以继续查询原任务，新的查询期限生效且没有新付费提交。
- [ ] 超时、待核实等未知终态不被当作失败或成功释放连接占位；明确终态后按实际状态推进队列。
- [ ] 前端能区分继续查询与重新生成，明确失败后的重新生成创建新任务并保留旧记录。
- [ ] 输入变更不会修改既有任务快照；每次生成更新节点的当前任务关联，旧任务迟到结果保留但不覆盖新任务展示。
- [ ] 用户删除节点时取消尚未提交的关联任务；删除与 worker 认领发生竞态时，由原子状态判定决定是否能取消，不出现报告已取消后仍被提交的行为。
- [ ] 已提交任务在节点删除后继续查询与保存，不重新创建已删除节点；切换画布、路由或组件卸载不触发删除取消。
- [ ] 生成成功但正在转存或保存失败的任务恢复后保留准确保存状态，不重新生成。转存执行的恢复由 03 负责，本票不依赖其重试交互即可完成上述验证。
- [ ] 重复挂载、浏览器重复查询及 worker 恢复不会增加生成提交次数，也不会由多个旧回调反复写入最新节点。
- [ ] 提供服务重启、等待超时及继续查询的运行说明，旧模型原调用行为保持兼容。

## Testing

- [ ] 沿用 01 的公开任务接口、真实临时数据库和外部服务替身；通过关闭并重建执行实例验证重启恢复，不能只改变内存标志模拟恢复。
- [ ] 在提交前、提交已发出但未取得响应、已取得平台 ID 三个阶段模拟中断，检查状态、连接占位和平台提交次数。
- [ ] 通过受控时间验证到期停止自动轮询、用户继续查询、原任务最终完成后释放占位，不使用长时间真实等待。
- [ ] 以用户操作场景验证刷新恢复、切换画布不取消、删除竞态以及两次生成反序完成后的结果归属。
- [ ] 保留画布持久化和既有模型行为回归；不新增 H3、文本迁移或全局任务历史页面。
