# 03: 结果保存失败与恢复

**What to build:** 创作者能明确区分生成成功与文件保存失败，在保存失败后单独重试转存；后台转存中断或部分成功后可以恢复。平台临时结果过期时明确告知，任何保存恢复都不重复生成。

**Blocked by:** 01 — 接通 Krea2 生图与可靠提交。

**Status:** ready-for-agent

## Context

依据父规格“统一模型层与平台中间层：RunningHub 生图首版”及 ADR 0002。01 已建立任务持久化、平台成功结果记录、首次 OSS 转存与独立保存状态。本票扩展该边界，实现恢复和重试；不依赖 02 的页面恢复或继续查询交互，可从已有任务记录独立验证。

用户已确认以公开任务接口和真实临时数据库为主测试入口，模拟平台 HTTP 及 OSS。后台只重试已有结果的下载保存，不对生成提交做补偿性重试。

## Acceptance criteria

- [ ] 生成成功与保存状态分别持久化，前端明确显示保存中、已保存或保存失败；失败原因不会误导用户为生成失败。
- [ ] 生成成功时已保存平台任务 ID、原始结果及可诊断信息；随后转存失败不丢失这些信息，也不重新占用已释放的生成并发名额。
- [ ] 用户可以针对原任务重试保存，使用已有结果重新下载及转存 OSS，平台生成提交次数保持不变。
- [ ] 重试操作具备并发控制，重复点击或多个后台执行者不会重复处理同一产物并破坏状态；稳定产物标识使中断恢复可判定已有保存结果。
- [ ] 多个返回产物中部分保存成功时，保留已成功产物及其引用，仅恢复未完成部分；不因重试清空已有结果。
- [ ] 下载与保存有超时及明确失败状态，不会永久卡在保存中；后台重启后可以识别未完成转存并继续保存，不重新提交生成。
- [ ] 平台临时结果过期或无法取回时明确显示“生成成功但结果保存失败”，保留诊断记录；不自动重新生成，用户可自行选择创建新任务。
- [ ] 保存完成后只向该任务记录写回产物；前端更新节点须核对当前任务关联，不覆盖新任务或重建已删除节点。
- [ ] 重试接口验证操作适用状态；仍在生成或没有成功结果的任务不能伪装为可重试保存。
- [ ] OSS 凭据和敏感平台响应不进入公开接口；任务输出包含前端需要的产物和保存状态。
- [ ] 文档说明保存重试与重新生成的区别、转存恢复启动方式及临时链接失效的限制；旧模型行为保持兼容。

## Testing

- [ ] 通过公开任务操作和真实临时数据库验证首次下载失败、OSS 失败、重复重试和最终保存成功，断言整个过程中生成提交始终只有一次。
- [ ] 模拟多个返回产物部分保存成功，确认重试保留成功引用且只补齐未完成产物，不用批量生图功能来构造依赖。
- [ ] 在上传前、上传成功但保存记录尚未完成、部分产物已保存时中断执行并重启，验证无重复生成、产物可恢复且状态一致。
- [ ] 模拟临时 URL 过期和下载超时，检查前端错误含义、任务生成成功状态以及无自动重新生成的副作用。
- [ ] 用少量前端操作验证重试按钮状态、保存成功展示及旧任务保存完成不覆盖新结果；复用 01 的任务边界而非新增内部函数模拟体系。

## Scope boundary

不新增存储供应商、全局历史页面或平台结果保留期承诺。02 负责画布整体恢复与任务生命周期，本票只恢复产物保存；两票可在 01 完成后分别开展，集成后验证两种恢复协同。
