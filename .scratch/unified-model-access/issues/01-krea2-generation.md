# 01: 接通 Krea2 生图与可靠提交

**What to build:** 创作者在统一前端选择 Krea2 模型、填写提示词与尺寸后，获得后台执行的生成任务，并看到转存到 OSS 的图片。同一平台连接默认串行，重复请求不会重复生成，提交结果不明确时明确显示待核实。旧模型继续保持原行为。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Context

父规格：统一模型层与平台中间层：RunningHub 生图首版。遵循 ADR 0001、0002 和项目词汇表。用户已确认三票拆分与统一任务接口测试边界；父规格的历史待确认文字不构成本票的新审批前置条件。

模型指可选择的生成能力；平台连接由管理员配置并供多个模型共用。首版使用后端配置登记模型，显式绑定适配器，不根据模型名称或域名猜测协议。只有新增 RunningHub 模型走新链路，文本及其他平台不迁移。

生图工作流 ID 为 2109340746494357505。用户提供的 API 导出确认提示词入口为节点 102 的 prompt，宽高为节点 10 的 custom_width、custom_height，使用自定义尺寸由 use_custom_resolution 控制，种子为节点 97 的 seed，输出节点为 103。导出可从父规格的来源链接取得；运行时不能依赖个人下载目录。节点尺寸约束须在实施时核实，不能将当前 1920 × 1080 推断为任意范围的证明。

## Acceptance criteria

- [ ] 管理员可以配置服务端平台连接并登记模型；前端统一模型列表显示 Krea2 及其配置状态，模型稳定标识与显示名称分离。
- [ ] 前端根据能力开放提示词与尺寸，显示实际生成尺寸；后端再次验证输入。当前 Krea2 不支持参考图，非空参考图及其他不支持的参数必须明确拒绝，不静默丢弃。
- [ ] 后端生成并保存实际提交的种子，前端不展示种子控件；新生成不因提示词相同而复用旧随机结果缓存。
- [ ] 提示词、尺寸、种子按确认的节点映射提交，数值与布尔类型正确；模型权重、LoRA、采样及旁路状态沿用导出。
- [ ] 依据同一站点官方工作流契约实现鉴权、提交和查询，不将标准模型的上传或响应格式套用到工作流，不捏造端点和字段。连接地址显式配置，国际站和国内站不混用。
- [ ] 创建请求持久化后立即返回本地任务标识；独立后台执行机制负责提交、查询和保存，不依赖浏览器或原 HTTP 请求持续存活。
- [ ] 通过增量数据库变更保存任务标识、请求标识、模型与配置版本快照、连接引用、有效输入、平台任务 ID、画布节点关联、时间、状态、平台结果及保存状态，不破坏已有数据。
- [ ] 任务快照不含凭据；新公开模型接口、任务响应和日志不泄漏密钥，平台诊断响应保留在服务端并脱敏。平台任务 ID 不发生数值精度丢失。
- [ ] 同一次请求标识在重复或并发请求下只创建一个任务；同标识不同输入被拒绝。明确重新生成使用新标识。
- [ ] 每个连接默认仅执行一个尚未明确结束的平台任务，其余排队；后台可配置并发。认领与占位具有原子性，worker 重入不导致重复提交。
- [ ] 已发出提交但未取得可靠结果时进入待核实，保留占位且不自动重提；平台明确失败可由用户重新生成。暂时性查询错误有限重试，确定性业务错误不无限重试。
- [ ] 基础查询有配置化期限和等待超时状态，不能无限轮询；继续查询交互由 02 完成，未知结束状态在此期间也不得释放占位。
- [ ] 成功结果转存 OSS 并呈现图片；生成与保存状态独立。首次转存失败时保留平台结果和任务 ID 并显示保存失败，不重新生成；重试保存与转存恢复由 03 完成。
- [ ] 任务关联与结果更新使用本地任务标识，为 02 的恢复及结果归属提供基础；不将正在执行的 Promise 作为唯一任务记录。
- [ ] 旧模型的接口和展示保持原行为，运行现有相关回归测试。H3 未补齐前不发布为可用模型，不阻塞本票。
- [ ] 提供运行后台执行机制、配置连接与 OSS 的说明，以及可复现的无凭据工作流资料。

## Testing

- [ ] 以统一生成任务公开接口为入口，使用真实临时数据库和模拟 RunningHub HTTP／OSS，覆盖创建、执行、查询、转存及前端取回结果。
- [ ] 验证无效输入不会触发平台提交；模拟端检查准确节点映射和数据类型；断言新公开响应不含凭据。
- [ ] 验证重复请求、并发认领、默认串行、配置版本快照以及提交响应丢失；直接断言平台付费提交次数，不只检查内部函数。
- [ ] 用统一前端完成选择模型到展示结果的场景检查，确保旧模型不被新适配器接管。
- [ ] 有用户配置的凭据与选定的最小测试时记录真实 Krea2 验收；否则明确列出真实联调待办，不声称已经实际生成。

## Scope boundary

本票交付首条可演示的完整链路；02 补齐恢复、超时操作及画布竞态，03 补齐保存失败的恢复操作。完整首版以三票共同验收，不因 01 成功路径通过便宣称全部故障恢复已完成。
