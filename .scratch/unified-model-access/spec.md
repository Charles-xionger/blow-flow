# 统一模型层与平台中间层：RunningHub 生图首版

Status: needs-info
Type: spec

规格内容已依据访谈及 ADR 0001、0002 综合完成。唯一发布确认项是 Testing Decisions 中的测试边界；用户确认后改为 ready-for-agent，无需重新访谈或额外 triage。H3 材料缺失不阻塞本规格的生图里程碑。

## Problem Statement

创作者希望通过一致的模型选择、参数输入和结果展示，使用不同平台的文本、图片、视频生成能力。现有模型注册、平台配置和业务路由之间仍混有按模型名称或域名判断调用方式的逻辑，新增平台容易要求同时修改多处业务代码。

RunningHub 上的自定义生成工作流需要准确的节点参数映射和异步任务处理。现有生成请求主要等待最终结果后返回，平台任务 ID 没有成为画布可恢复的任务记录；刷新页面或服务重启后无法可靠接回任务。生成成功后的文件保存失败也需要与生成失败区分，以免重复生成和计费。

用户希望在现有工程中建立清晰边界，先让自己的 Krea2 生图工作流通过统一前端可用，同时为之后接入修正后的 H3 视频工作流及其他平台保留扩展位置。首版不能依赖尚未提供的 Gemini 接入或 H3 修正版。

## Solution

创作者继续在画布中选择模型、填写提示词和模型支持的参数、点击生成。平台凭据由管理员统一配置，工作流 ID、节点字段以及平台上传、提交和查询协议留在后端。

模型层描述可选择的生成能力及参数；统一任务服务负责验证、排队、持久化和恢复；平台中间层按显式适配器标识调用平台并转换状态、结果与错误；产物保存使用现有 OSS。首批只有新增 RunningHub 模型走新链路，旧模型保持现有行为。

本规格的可交付里程碑是 RunningHub Krea2 生图完整链路。H3 的低分辨率、多参考图等目标作为后续扩展约束保留，修正版到达且验证前不向用户发布一个看似可用的视频模型。

## User Stories

1. As a 创作者, I want 在统一模型列表中选择 Krea2 生图能力, so that 我能直接使用已有 RunningHub 工作流。
2. As a 创作者, I want 用熟悉的提示词输入和生成按钮操作, so that 我不需要学习平台 API 或 ComfyUI 节点字段。
3. As a 创作者, I want 只看到所选模型支持的参数, so that 我不会填写实际不会生效的配置。
4. As a 创作者, I want 调整生图尺寸并看到实际生成尺寸, so that 我能控制输出画幅。
5. As a 创作者, I want 不支持的输入在提交前被明确指出, so that 我的参考图或其他设置不会被静默忽略。
6. As a 创作者, I want 每次生成由后台产生并记录种子且不展示种子控件, so that 界面简洁并保留排查依据。
7. As a 创作者, I want 提交后立即获得可追踪任务, so that 我无需保持一次 HTTP 请求直到生成完成。
8. As a 创作者, I want 看到本地排队与平台执行的区别, so that 我知道任务正在等待哪里。
9. As a 创作者, I want 刷新或重新打开画布后恢复任务状态, so that 我不会丢失正在生成的任务。
10. As a 管理员, I want 服务重启后恢复已有平台任务的查询, so that 维护服务不会产生重复生成。
11. As a 创作者, I want 重复的同一次提交请求不会创建多个平台任务, so that 网络重试不会造成重复计费。
12. As a 创作者, I want 提交结果不明确时看到待核实状态, so that 我不会将未知结果误认为失败并被系统自动重提。
13. As a 创作者, I want 等待超时后继续查询原任务, so that 我无需重新支付生成费用来取得结果。
14. As a 管理员, I want 未明确结束的超时任务保留并发占位, so that 后续任务不会突破本地连接限制。
15. As a 创作者, I want 明确失败后能够重新生成, so that 新的尝试有独立记录。
16. As a 创作者, I want 每次任务保留提交时的输入快照, so that 后续编辑不会改变正在执行任务的含义。
17. As a 创作者, I want 旧任务的迟到结果不覆盖新任务, so that 节点始终对应最近一次生成。
18. As a 创作者, I want 删除节点后取消尚未提交的任务, so that 不再需要的工作不会被继续提交。
19. As a 创作者, I want 删除节点后已提交任务仍被跟踪且不重建节点, so that 后台保存结果而不打乱画布。
20. As a 创作者, I want 生成结果保存在项目自己的存储中, so that 展示不长期依赖平台临时链接。
21. As a 创作者, I want 文件转存失败时单独重试保存, so that 无需重新生成。
22. As a 创作者, I want 临时链接过期时明确看到保存失败, so that 我能自行决定是否重新生成。
23. As a 管理员, I want 一个平台连接供多个模型共用, so that 不必为每个工作流重复配置凭据。
24. As a 管理员, I want 平台密钥保留在服务端, so that 新模型目录、任务响应和日志不会暴露凭据。
25. As a 管理员, I want 每个连接默认串行且并发数可配置, so that 可以按实际账号能力管理负载。
26. As a 维护者, I want 用配置登记工作流及输入映射, so that 新增同协议能力不需要改画布业务分发逻辑。
27. As a 维护者, I want 模型使用稳定标识并显式绑定适配器, so that 修改展示名称不会改变协议选择或破坏旧任务。
28. As a 维护者, I want 既有模型继续使用原行为, so that 首批接入不要求同时迁移文本或其他平台。
29. As a 维护者, I want 缺失的 H3 配置被明确标记为待补充, so that 不会为了完成开发而猜测节点参数或复制示例素材。
30. As a 创作者, I want 后续视频支持按顺序编号和调整参考图, so that 提示词中的图像引用与提交顺序一致。
31. As a 创作者, I want 后续视频实际以 480p、720p 或 1080p 档位生成, so that 不必先生成 2K 再缩小文件。
32. As a 创作者, I want 后续视频的分辨率档位、画幅和时长由实际模型能力约束, so that 统一界面也能准确表达不同模型的差异。

第 30–32 项为 H3 后续里程碑目标，本次只保留扩展边界，不将未验证的视频能力计入生图首版验收。

## Implementation Decisions

### 范围与职责

- 模型指用户可选择的生成能力，既可对应厂商模型，也可对应生成工作流；接入类型在内部明确区分。
- 模型目录由服务端提供公开能力描述。新增链路使用稳定模型标识、类别、连接引用、适配器标识、参数规则和工作流映射；显示名称不用于推断协议。
- 平台连接由管理员配置，包含服务端地址、凭据来源、并发限制及超时设置。前端只接收可用性和公开能力，不接收密钥。
- 新的模型配置与已有模型目录在前端共同展示，但运行分发边界明确，旧模型不被新逻辑误接管。未配置凭据的模型显示未配置状态，不能进入付费提交阶段。
- 首版通过后端配置文件登记模型；不构建可视化工作流导入器和参数映射编辑器。
- 统一任务服务与画布数据结构解耦。请求表达模型及生成输入，画布和节点关联用于恢复及展示，不把 React 组件或整张画布传给适配器。
- 适配器负责平台鉴权、必要的素材上传、提交、状态查询、结果解析和错误转换；业务节点不解析平台原始响应。
- 模型类别保留文本、图片、视频。首版交付图片执行链路，不把所有未来文本流式行为硬套进媒体轮询协议。

### 生图能力与可信来源

- 首批模型为用户提供的 Krea2 田园风格 MJ 感工作流，平台工作流 ID 为 2109340746494357505。
- 已核实的 API 导出中，提示词入口为节点 102 的 prompt；尺寸由节点 10 的 custom_width、custom_height 及 use_custom_resolution 控制；种子为节点 97 的 seed；图片输出节点为 103。
- 提示词节点直接进入文本编码器；画布中旁路的 LLM 节点没有进入 API 执行图。不得将被旁路逻辑重新接入或使用旧编码器文本替代用户提示词。
- 模型权重、LoRA 组合和采样配置沿用用户工作流，首版不向用户开放这些内部参数。
- 当前 API 导出为文生图，不含参考图入口。统一层可表达有序参考图，但此模型收到非空参考图必须明确拒绝，不静默丢弃，不伪装支持图生图。
- 允许用户调整尺寸；提交前依据节点实际约束校验。导出中 1920 × 1080 是当前值，不构成任意尺寸范围的证明。实施者应核实相关节点定义后设置边界和对齐规则，不从文件名推断规则。
- 后台生成并记录实际发送的种子，不提供种子显示或编辑控件。新任务不得因旧的提示词缓存直接返回上一次随机生成结果。
- 用户选择、后端有效参数与实际提交值应保持一致；不支持的参数、批量数量或功能应明确拒绝，而非忽略。首版不增加未讨论的批量调度功能。
- 自定义工作流参数依据用户 API 导出及正式工作流接口文档；标准模型端点若以后接入，模型端点和参数唯一依据官方公开模型注册表。不得将标准模型上传、查询响应结构直接套用于工作流协议。
- 工作流 API 的鉴权、素材上传返回引用、提交和查询契约须按同一站点正式文档核实，尤其区分上传文件名与公网 URL。用户提供的是国际站链接，连接地址显式配置，不混用站点。
- 模型配置版本及本次有效映射随任务保存，以免配置变更后用新映射解释旧任务。凭据不进入快照。

### 统一接口与持久化记录

- 新链路提供公开模型目录、创建生成任务、查询任务，以及继续查询、重试保存和取消未提交任务的操作。具体 HTTP 路径在实现时确定，不要求改动旧接口契约。
- 创建请求使用可在客户端保存和重用的请求标识，服务端保证同一次请求幂等；网络响应丢失后可找回原记录。相同标识但不同输入不能作为新提交接受。用户明确重新生成使用新标识。
- 创建接口在任务持久化后返回本地任务标识与状态；后台执行不依赖该请求连接存活。
- 任务至少保存本地标识、请求标识、模型及配置版本快照、连接引用、画布与节点关联、有效输入及种子、平台任务 ID、生命周期状态、时间与查询期限、平台结果和转存结果、可诊断错误。
- 平台任务 ID 以不损失精度的形式保存。平台原始响应保留在服务端诊断记录中，剔除凭据；公开响应仅包含界面所需字段。
- 持久化使用现有数据库设施的增量变更，不重置现有画布、模型配置或缓存数据。
- 采用可独立持续执行并在重启后恢复的后台任务机制。部署与启动说明必须覆盖该机制，不能只依赖请求结束后的内存 Promise 或浏览器轮询触发执行。
- 队列认领和连接并发占位应具备原子性，避免多个 worker 或重入导致同一任务重复提交。进程异常恢复时，已进入不确定提交阶段的任务不得重新发送。

### 生命周期与排队规则

- 对外区分本地排队、提交中、平台处理中、待核实、等待超时、生成成功、生成失败、未提交已取消等含义；平台原始状态由适配器归一化。
- 转存状态单独记录为未开始、保存中、已保存或保存失败，不用一个失败状态混淆生成与存储。
- 每个平台连接默认仅允许一个尚未明确结束的平台任务，其余本地排队；并发可配置，此默认值不是 RunningHub 官方限制。
- 已取得平台任务 ID 的任务在页面刷新、画布重新打开、后台重启后继续查询原任务。
- 已发出提交但没有可靠结果，或崩溃后无法确定是否已提交的任务进入待核实状态；不自动重提，不假定平台未收到。待核实任务不能被当作确定失败释放连接占位。
- 查询期限可配置。超时后停止自动查询并显示等待超时，允许继续查询原任务；平台状态未明确前仍占用连接名额。
- 查询的暂时性网络故障可有限重试，但不无限轮询；确定性业务错误不反复重试。提交操作不使用可能产生重复付费任务的自动重试。
- 明确失败后用户重新生成，创建新的本地记录与平台任务。旧记录仍保存，不冒充恢复原任务。
- 平台已明确生成成功后释放生成并发占位；转存失败只影响保存状态，不要求再次生成。

### 统一前端与结果关联

- 新链路在现有画布交互中提供模型选择、能力驱动参数、实际尺寸、任务阶段与错误提示；不新增 RunningHub 专属节点编辑器。
- 前端模型能力控制与后端校验一致；客户端隐藏字段不能代替服务端验证。
- 前端保存可恢复的任务关联，支持短暂网络失败后找回创建结果，避免刷新后只有无法恢复的“生成中”布尔状态。
- 同一节点每次生成形成独立输入快照，后续编辑不改变已有任务。只有最近一次任务可以更新该节点的当前展示，迟到的旧结果只保留在任务记录中。
- 删除节点时取消尚未提交的关联任务。若已提交则继续跟踪和保存，不重建节点。取消与认领并发发生时须以持久化状态为准，不能先向用户报告取消后仍提交。
- 切换画布和卸载组件不等于删除节点，不自动取消后台任务。
- 重复提交、继续查询、重试保存与重新生成在行为上明确区分；暂不额外建设全局任务历史管理页面。

### 产物保存

- 生成成功后保留平台原始结果和任务 ID，并转存到现有 OSS，记录保存后的产物引用。
- 保存失败时只重试下载及转存，不能再次调用生成提交。部分文件保存成功后，重试不丢失已有结果。
- 平台临时文件过期或不可取回时，明确表示生成成功但保存失败，由用户决定是否重新生成。
- 转存过程有超时和可恢复状态；重启恢复不能把生成成功误判为需要重新提交。

### H3 后续边界

- 用户会补充修正后的 H3 API 工作流。当前文件连接了三张图片，不能直接据此声明产品必须提供三张，也不能用占位示例图片补足输入。
- 后续先以一张参考图联调，支持的最大数量、可选输入、时长及尺寸范围必须依据新工作流及节点定义核实。
- 视频需实际低分辨率生成，目标档位为 480p、720p、1080p；画幅单独选择，按节点要求对齐像素并显示实际尺寸。不以 2K 生成后缩小代替需求。
- 参考图列表编号且可调整顺序，后端保持提交顺序。时长按可用能力开放，工作流需要帧数对齐时准确表达目标时长与实际时长的差别。
- 官方 H3 标准 API 不是首批替代方案；此前优先官方接口的选择已被实际低分辨率要求取代。

## Testing Decisions

测试边界提案，等待用户确认：以统一生成任务的公开接口为主要测试入口，贯穿输入验证、真实临时数据库、任务执行与查询、产物状态；仅替换外部 RunningHub HTTP 服务、OSS 及必要的时间控制。前端以少量用户操作场景验证恢复及结果归属。避免为每个内部函数单独建立一套模拟测试。

- 好的测试检查用户可观察状态、返回产物和外部副作用，尤其断言付费提交次数；不依赖内部函数调用顺序、私有类结构或组件快照。
- 模型目录与输入校验：稳定标识选择正确配置，未配置连接不可提交，缺失提示词、非法尺寸、不支持的参考图或参数不会产生平台任务，公开响应不包含凭据。
- Krea2 协议契约：真实导出作为映射依据，提示词、宽高及种子进入正确节点字段，数值和布尔保持正确类型，上传或查询契约不能混用标准模型结构。平台请求体可在外部 HTTP 替身处断言，因为它是第三方边界。
- 成功路径：创建立即返回任务标识，后台提交一次，状态查询推进到生成成功并完成 OSS 保存，前端可以取得持久化结果。
- 排队与幂等：两个同连接任务按配置串行；重复请求、worker 重入、响应丢失后恢复均不增加同一次任务的提交次数；真正重新生成产生新任务。
- 故障恢复：重启后已持有平台 ID 的任务只查询不提交；提交后断线或崩溃进入待核实并保留占位；未知平台状态不被当作成功或失败吞掉。
- 超时：借助可控制的时间验证停止自动查询、保留占位以及用户继续查询原 ID，恢复查询不会提交新任务。
- 文件保存：模拟生成成功但下载失败、OSS 失败、临时 URL 过期以及重启中的转存；重试保存的生成提交次数保持不变。
- 画布行为：刷新与重新打开后恢复；切换画布不取消；节点删除只取消未提交任务；删除后不重建；两个任务反序完成时旧结果不覆盖最新任务。
- 兼容回归：已有模型不经过新适配器，不改变原请求和结果展示；使用已有画布持久化与连接行为测试作为回归基线。
- 测试先例：仓库已有使用 Node 内置测试运行器和 TypeScript 转译加载小模块的行为测试，覆盖画布持久化、连接策略和状态更新。新测试可沿用运行方式，但必须增加临时数据库与外部 HTTP 替身，不能仅检查静态源码。
- 真实验收：在用户提供有效平台连接、OSS 配置并选定最小测试后，执行一次 Krea2 生图并核对实际输出。没有凭据时交付自动化模拟验证与明确的真实联调待办，不声称已真实生成。

生图里程碑通过条件：统一前端可选择该模型；输入准确映射；任务独立执行并可恢复；串行、幂等及不确定提交规则生效；结果完成转存或有可重试的准确保存状态；旧模型回归通过；凭据不进入新公开接口；真实联调状态如实记录。H3 不计入此里程碑的完成条件。

## Out of Scope

- H3 修正版到达前的视频参数定案、可用模型发布与真实视频生成验收。
- 其他平台真实接入、现有 Gemini 或文本链路迁移，以及“已经验证跨平台通用性”的宣称。
- 自动平台路由、模型降级、价格比较、套餐、按用户隔离凭据及多租户权限体系。
- 可视化工作流导入、节点参数映射编辑器、任意 ComfyUI 画布编辑与工作流自动修复。
- 暴露 LoRA、底层权重或采样器配置，以及种子编辑界面。
- 未核实的平台取消操作、删除节点后自动撤销平台费用、提交不明确时自动付费重试。
- 用生成后缩小冒充低分辨率生成、静默截断参考图或用示例图片填空。
- 全局任务历史管理页面、批量生成调度、全量旧接口安全重构与无关画布重构。
