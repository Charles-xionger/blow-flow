# 节点三层通用组件

Status: ready-for-agent

## Problem Statement

创作者在画布上看到的各类节点，外观和操作方式并不统一：操作按钮藏在图片悬浮层里，配置和运行散落在各节点自己的面板中，某些节点拖动时还会继续显示面板。提示词只是普通文本框，创作者无法指明“这里用哪张参考素材”；连接文本节点后，手写的提示词还会被静默忽略。

维护者同样受影响。每个生成节点各自拼装预览、面板、运行和任务恢复逻辑，改一处通用行为要改很多个大文件，样式也容易走样。

## Solution

所有节点（分组除外）改用同一个三层结构：节点工具栏、节点展示区、节点控制台。节点控制台再分三层：连接的上游节点、可用 `@` 引用节点的提示词编辑器、配置项和运行。

外观采用原型方案 A（紧凑悬浮）。节点工具栏和节点控制台只在节点单选且未拖动时浮现，不影响节点显示尺寸，连接点和连线保持稳定。编辑器里看到的内容，就是发送给模型的内容，不再有隐藏的合并规则。

对维护者，通用外壳和控制台负责所有共同行为，每类节点只声明自己的展示内容、配置项和运行方式。

## User Stories

### 节点结构与显示

1. 作为创作者，我希望所有节点使用相同的三层结构，这样换一种节点也不用重新学习操作。
2. 作为创作者，我希望单选节点时才出现节点工具栏和节点控制台，这样画布在平时保持干净。
3. 作为创作者，我希望多选节点时不出现节点工具栏和节点控制台，这样批量操作不被遮挡。
4. 作为创作者，我希望拖动节点时节点工具栏和节点控制台隐藏，这样拖动时能看清位置。
5. 作为创作者，我希望打开节点控制台时节点展示区不变形，这样连接点和连线不会跳动。
6. 作为创作者，我希望节点工具栏和节点控制台随画布缩放，这样它们和节点的相对位置始终一致。
7. 作为创作者，我希望在节点控制台内滚动、选文字、点按钮时不会拖动节点或平移画布，这样编辑不被打断。
8. 作为创作者，我希望分组保持现有的虚线框形式，这样它仍然只是整理节点的容器。

### 节点工具栏

9. 作为创作者，我希望在节点工具栏里预览图片或视频，这样不用先在结果上悬停才能找到入口。
10. 作为创作者，我希望在节点工具栏里下载结果，这样下载入口的位置固定。
11. 作为创作者，我希望在节点工具栏里把结果保存为角色，这样常用角色可以复用。
12. 作为创作者，我希望复制、删除和分组仍在右键菜单里，这样对节点本身的操作和对内容的操作不混在一起。
13. 作为创作者，我希望没有内容时，依赖内容的工具栏操作不可用，这样不会点到无效按钮。

### 连接的上游节点

14. 作为创作者，我希望在节点控制台第一层看到所有上游节点的缩略图，这样知道这次生成用到了什么。
15. 作为创作者，我希望悬停缩略图时看到编号和名称，这样能分清“图片1”是哪个节点。
16. 作为创作者，我希望从缩略图直接断开连接，这样不用回到画布上找连线。
17. 作为创作者，我希望拖动缩略图调整顺序，这样能决定谁是“图片1”。
18. 作为创作者，我希望调整顺序后编辑器里的引用编号自动更新，这样编号和实际素材始终对应。
19. 作为创作者，我希望没有上游节点时不显示这一层，这样节点控制台不留空白。
20. 作为创作者，我希望连接的参考素材都用于生成，无论提示词里是否引用，这样连上就生效。

### 提示词编辑器与节点引用

21. 作为创作者，我希望输入 `@` 时弹出已连接的上游节点列表，这样不用记名称。
22. 作为创作者，我希望用方向键和回车选择引用，这样不用离开键盘。
23. 作为创作者，我希望节点引用显示为带缩略图的标签，这样在文字中一眼能认出。
24. 作为创作者，我希望删除节点引用不会断开连线，这样改提示词不会改变画布结构。
25. 作为创作者，我希望断开连线后节点引用变成断开时显示名称的普通文本，这样提示词不会出现失效状态。
26. 作为创作者，我希望重新连线后那段普通文本保持不变，这样不会有内容被悄悄替换。
27. 作为创作者，我希望删除上游节点时按断开连线处理，这样行为一致。
28. 作为创作者，我希望连接文本节点时自动插入它的节点引用，这样连接后立即可见它会被发送。
29. 作为创作者，我希望删除文本节点的引用后，这段文本不再发送，这样我能控制提示词的内容。
30. 作为创作者，我希望手写提示词和连接的文本都能发送，这样不会再有内容被静默丢弃。
31. 作为创作者，我希望运行时使用上游文本节点的当前内容，这样改了文本不用重新引用。
32. 作为创作者，我希望用中文输入法输入时不被打断，也不误触发菜单，这样中文写作顺畅。
33. 作为创作者，我希望粘贴内容时只保留纯文本，这样外部样式不会混进提示词。
34. 作为创作者，我希望能撤销和重做编辑器内的输入，这样改错了可以恢复。
35. 作为创作者，我希望没有上游节点时输入 `@` 就是普通字符，这样不会弹出空菜单。

### 配置与运行

36. 作为创作者，我希望模型、生成尺寸、数量等配置和运行按钮在同一行，这样节点控制台保持紧凑。
37. 作为创作者，我希望配置项只显示当前模型支持的内容，这样不会选到无效组合。
38. 作为创作者，我希望提示词展开后为空时不能运行，这样不会发出无效请求。
39. 作为创作者，我希望首尾帧缺图时不能运行，这样节点特有的要求仍然生效。
40. 作为创作者，我希望运行状态、错误、任务恢复和重试保存仍在节点控制台里可用，这样现有的可靠性行为不退化。
41. 作为创作者，我希望生成中节点展示区显示进度，这样不打开节点控制台也知道状态。

### 各类节点

42. 作为创作者，我希望文生图、图生图、文生视频、图生视频、首尾帧节点都有完整的三层节点控制台，这样生成操作一致。
43. 作为创作者，我希望首尾帧节点仍能交换首帧和尾帧，这样节点特有的能力不丢失。
44. 作为创作者，我希望文本节点的节点控制台只有编辑器，这样写文本时没有多余控件。
45. 作为创作者，我希望创意描述和分镜节点有编辑器、配置和运行，但没有连接层，这样符合它们没有输入的特点。
46. 作为创作者，我希望原图和角色节点没有节点控制台，只用节点工具栏，这样它们保持简单。

### 保存与复用

47. 作为创作者，我希望节点引用和参考素材顺序随画布保存，这样重新打开项目时内容不变。
48. 作为创作者，我希望单独复制节点时，副本的节点引用变成普通文本，这样副本不会指向它没有连接的节点。

### 维护者

49. 作为维护者，我希望新增节点类型时只声明展示内容、配置项和运行方式，这样不用重写通用行为。
50. 作为维护者，我希望特殊节点能往插槽里放自定义内容，这样不用为了少数差异扩展配置。
51. 作为维护者，我希望编辑器的具体实现不进入画布数据，这样以后可以更换编辑器。
52. 作为维护者，我希望未选中的节点不挂载编辑器，这样大画布的性能不下降。

## Implementation Decisions

### 视觉

- 采用原型方案 A：节点工具栏是展示区上方居中的图标胶囊；节点控制台是展示区下方、约 440 宽的悬浮面板，圆角卡片。
- 连接层用小方块缩略图，悬停显示编号和名称，并提供断开操作。
- 配置项是一行紧凑的文字控件，运行按钮在行末。

### 通用外壳

- 提供组合式节点外壳，含节点工具栏、节点展示区、节点控制台三个插槽。xyflow 继续负责定位、拖动、选择和连接点。
- 外壳统一决定：节点工具栏和节点控制台的显示条件（单选且未拖动）、拖动时的绘制抑制、选中和状态样式、标题、连接点、快捷添加。
- 节点显示尺寸只指节点展示区；节点工具栏和节点控制台绝对定位，不参与节点测量。
- 节点控制台负责三层布局和通用运行区（运行状态、错误、任务恢复、重试保存），每层都可选，节点没有上游连接时不显示连接层。
- 每类节点只声明展示内容、节点工具栏操作、配置项、运行方法和节点特有的运行条件。不做纯配置驱动，特殊内容直接放进插槽。
- 现有生成节点里的运行与任务逻辑沿用现有 hook，不改变生成接口。

### 提示词数据模型

- 提示词保存为分段结构，见 ADR 0005。下面的类型形状来自原型：

```ts
type Segment = { text: string } | { ref: string }; // ref 为上游节点 ID
```

- 分段结构替换节点数据里的提示词字符串。读取到旧字符串时当作单个文本段，不做单独的迁移流程，也不为此增加迁移测试。
- 提示词模块是纯函数模块，负责：按类型编号、解析引用、断线转文本、展开成发送文字。不依赖编辑器和 React。
- 发送文字规则：图片引用转成 `图片N`；文本引用展开成上游文本节点的当前内容，上游内容里的引用逐层展开；展开中再次遇到同一节点时，改用名称文本，防止循环。

### 连线与节点引用

- 连线是唯一的事实来源。`@` 只能选已连接的上游节点，节点引用不会创建连线，删除节点引用也不会断线。
- 连线能否建立仍由现有节点定义的接受类型决定，节点引用不额外限制。
- 以下规则放在画布 store 内，与连线变更在同一次状态更新中完成：
  - 连接文本节点时，在目标节点提示词末尾追加节点引用。
  - 连线断开或上游节点删除时，把目标节点提示词里对应的节点引用变成 `@名称` 文本，名称取断开时的显示名称。
  - 单独复制节点时，不复制连线，副本里的节点引用变成文本。
- 参考素材按类型分别编号，默认按连线先后，可在连接层拖动调整。顺序用目标节点连入连线的相对顺序表示，随画布保存。
- 角色节点作为图片类参考素材参与编号。

### 编辑器

- 使用 Tiptap，只在节点控制台打开时挂载，未选中的节点只显示纯内容。
- 分段结构和 Tiptap 文档只在编辑器边界互相转换，Tiptap JSON 不进入画布数据。
- 编辑器保留中文输入法组合输入，粘贴时只保留纯文本，节点引用作为不可编辑的整体标签。
- 编辑器内撤销和重做由编辑器提供。

### 各类节点范围

| 节点 | 节点展示区 | 节点控制台 |
| --- | --- | --- |
| 文生图、图生图、文生视频、图生视频、首尾帧 | 生成结果 | 连接层、编辑器、配置和运行 |
| 文本 | 文本内容 | 只有编辑器 |
| 创意描述、分镜 | 状态和结果摘要 | 编辑器、配置和运行 |
| 原图 | 图片 | 无 |
| 角色 | 角色信息 | 无 |
| 分组 | 不使用三层结构 | 无 |

### 节点工具栏内容

- 放对节点内容的操作：预览、下载、保存为角色。这些操作从图片悬浮层迁移过来，迁移后去掉悬浮按钮。
- 复制、删除和分组留在右键菜单。
- 预留重绘这类编辑操作的位置，这次不新增功能。

### 迁移方式

- 按 expand–contract 进行：新外壳与旧外壳并存，先用文生图节点打通，再分批迁移其余节点，最后删除旧外壳和不再使用的面板。

## Testing Decisions

- 好的测试只验证外部行为：用户在画布上看到和做到什么，以及 store 操作后的画布数据和发送文字。不测试插槽结构、CSS 类名和 Tiptap 内部。
- 只用两个接入点：

| 接入点 | 验证内容 |
| --- | --- |
| 真实画布页（Playwright） | 三层的显示和隐藏、`@` 菜单、中文输入法、引用标签、悬停提示、缩略图拖动排序、运行、拖动时隐藏 |
| 画布 store 和提示词模块（`node --test`） | 连线插入引用、断线转文本、删除上游节点、复制节点、按类型编号、展开成发送文字、循环保护、空提示词不能运行 |

- 外壳不单独测试，它的行为由画布页测试覆盖。
- 分段结构和 Tiptap 的互转由画布页测试覆盖，方式是输入后检查发送内容，这样更换编辑器时测试不用改。
- 性能沿用现有画布性能测试，只补一条“未选中的节点不挂载编辑器”。
- 现有参考：`krea2-panel`、`h3-panel`、`canvas-save` 浏览器测试；`canvas-*` 的 `node --test` 测试。现有依赖旧面板结构或提示词字符串的测试，随迁移一起更新。

## Out of Scope

- 新增重绘、局部编辑等节点工具栏功能。
- 改变生成接口、生成任务的存储和恢复逻辑。
- 为旧画布编写迁移流程。
- `@` 任意节点时自动连线。
- 引用素材库或其他项目的内容。
- 按模型定制引用文字格式。只有某个模型确实需要时才单独适配。
- 分组的样式改造。
- 画布顶栏、侧边栏和右键菜单的样式改造。
