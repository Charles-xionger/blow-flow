# 创作画布迁移 IndexedDB，并可靠同步服务端数据库

Status: ready-for-agent
Type: spec

## Problem Statement

用户期望新增、编辑和删除节点后自动保存，重新打开画布仍能恢复。最初的问题是编辑只写浏览器草稿，没有自动写服务端数据库。本次对话中的初步修复已增加自动保存，但仍有以下缺口：

- 本地草稿使用 localStorage 的单一画布快照，不能持久保存多个画布的待同步内容。
- 同步队列只在内存中，刷新后不能完整恢复失败或尚未确认的请求。
- 首次创建已在服务端成功但响应丢失时，重试可能创建重复项目。
- 一个画布保存失败会阻塞其他画布，单纯“本地已保存”也不能说明服务端已写入。

迁移 IndexedDB 解决本地持久化和恢复问题；仍须完善服务端同步、请求幂等和确认机制，才能解决“不进数据库”。

## Solution

采用“内存即时编辑 → IndexedDB 本地提交 → 后台同步 → 服务端 SQLite 确认”的保存流程。

用户编辑时界面立即响应。持久化成功后显示“已保存到本地，待同步”；只有服务端确认当前修改版本写入后才显示“已同步”。断网时继续保留本地草稿，刷新后恢复；联网后自动补传。每张画布独立排队，一个画布失败不影响其他画布。

升级时迁移已有 localStorage 草稿，不覆盖较新的 IndexedDB 数据。数据库和浏览器存在冲突时保留双方内容，并提供明确的恢复选择。

## User Stories

1. As a 创作者, I want 新增节点后自动保存, so that 无须反复点击保存。
2. As a 创作者, I want 输入和拖拽立即响应, so that 保存不会阻塞操作。
3. As a 创作者, I want 节点内容、位置、连线、项目名称和视角被保存, so that 能恢复完整画布。
4. As a 创作者, I want 删除最后一个节点也能同步, so that 数据库不会重新出现旧节点。
5. As a 创作者, I want 本地草稿保存到 IndexedDB, so that 可以按画布管理草稿和待同步内容。
6. As a 创作者, I want 旧 localStorage 草稿自动迁移, so that 升级不会丢失已有创作。
7. As a 创作者, I want 重复启动不会重复迁移, so that 不会产生重复草稿或覆盖新内容。
8. As a 创作者, I want 迁移失败时保留原草稿, so that 可以修复或导出恢复。
9. As a 创作者, I want 断网时仍能编辑已经打开的画布, so that 创作不依赖持续联网。
10. As a 创作者, I want 本地提交完成后刷新能恢复草稿, so that 未同步修改不会因为页面刷新而丢失。
11. As a 创作者, I want 网络恢复后自动补传, so that 本地修改最终进入服务端数据库。
12. As a 创作者, I want 多张画布的待同步内容独立保留, so that 切换项目不丢失未同步修改。
13. As a 创作者, I want 一个项目同步失败不影响其他项目, so that 可以继续保存其他创作。
14. As a 创作者, I want 保存过程中继续编辑的内容也被提交, so that 网络延迟不会吞掉新修改。
15. As a 创作者, I want 新项目重试保存不会创建多个项目, so that 项目列表保持清晰。
16. As a 创作者, I want 服务端已保存但响应丢失后能安全重试, so that 不重复创建或回退内容。
17. As a 创作者, I want 旧响应不会把新修改标记为已同步, so that 保存状态真实可信。
18. As a 创作者, I want 切换画布后迟到的请求仍归属原画布, so that 不会串写项目。
19. As a 创作者, I want 明确区分本地保存、正在同步、已同步和失败, so that 知道内容保存到了哪里。
20. As a 创作者, I want 保存按钮和快捷键立即尝试保存当前修改, so that 可以主动确认保存结果。
21. As a 创作者, I want 浏览器存储不可用时收到提示并可导出, so that 不会误以为草稿已安全保存。
22. As a 创作者, I want 两个标签页或设备的冲突不会静默覆盖内容, so that 双方修改都有恢复机会。
23. As a 创作者, I want 服务端删除的项目不会被旧离线请求自动复活, so that 删除意图被保留。
24. As a 创作者, I want 服务端同步完成后在没有本地缓存的环境中也能读回节点, so that 保存结果不依赖当前浏览器。
25. As a 创作者, I want 保存和恢复画布不会重新提交生成任务, so that 不产生额外生成费用。
26. As a 创作者, I want 加载草稿期间不会把默认空画布写回, so that 初始化不会破坏已有数据。

## Implementation Decisions

### 责任与接口

- 内存 store 负责当前交互；本地草稿仓库负责 IndexedDB 事务、迁移、恢复和待同步记录；同步协调器负责请求顺序、重试和服务端确认；服务端画布存储负责持久化、版本校验和幂等。
- 保留现有画布 store 操作接口和保存入口，将原同步 localStorage 适配器替换为可等待完成的本地仓库。调用方必须等待事务提交，不能仅等待写请求入队。
- 自动保存、保存按钮和快捷键走同一协调器。SSR 不访问浏览器存储；主题等小型偏好仍可保留在 localStorage。
- 不迁移生成任务恢复记录、平台连接或其他独立存储。本次处理创作画布数据，遵守既有持久化生成任务 ADR，不引入新的生成任务提交行为。

### IndexedDB 数据与迁移

- 建立带 schema 版本的 IndexedDB，分开保存画布草稿、待同步操作和迁移元数据。
- 草稿至少包含稳定画布 ID、完整画布快照、本地单调递增版本、最后确认的服务端版本、最后确认的本地版本和更新时间。时间只用于展示，不用于决定谁覆盖谁。
- 待同步操作包含持久化请求 ID、画布 ID、发送快照、本地版本、预期服务端版本和重试信息。已发送操作的身份与内容不可变；其后的编辑保留为最新待发送版本。
- 同一事务写入草稿和其待同步状态，防止出现“本地显示已保存但没有可恢复的同步记录”。确认响应时在另一事务内更新确认版本并清理对应操作，不删除更新的待同步内容。
- 已有数据库画布保留原 ID；全新画布在本地首次需要保存时生成稳定 ID，并在本地与服务端共同使用。空白新画布不自动创建服务端记录。
- 首次启动读取旧 canvas-storage 数据，验证原有 envelope 和画布结构后导入。迁移成功标记与导入记录同事务提交；再次启动跳过已完成迁移。
- 不覆盖同 ID 的既有 IndexedDB 草稿。旧数据与已有记录不一致且无法判断先后时，保留为独立恢复副本，不使用客户端时间强行判定新旧。
- 迁移完成后停止写旧 localStorage 画布键，旧原文保留作备份；迁移标记防止后续重新导入。损坏数据或事务失败不删除原文，显示可恢复错误。
- 旧草稿带服务端 ID 但没有可信服务端版本时，不直接上传覆盖服务端：联网读取并比较持久化字段；相同则建立版本基线，不同则保留本地恢复副本并提示选择。离线时保留草稿，等待核对。

### 初始化和提交时机

- 初始化先打开数据库并迁移，再根据 URL 项目身份加载本地草稿，随后读取服务端并核对版本。编辑器在本地恢复完成前显示加载状态，禁止默认空状态触发自动写入。
- 本地有待同步内容时不得被服务端读取结果直接替换；没有本地待同步内容时可采用服务端新版本。
- 沿用约 500ms 合并窗口；持续非拖拽编辑最多约 2s 触发一次本地提交。拖拽等连续交互期间合并中间状态，交互结束后提交最终位置。
- 本地提交完成后安排同步；本地与服务端合并使用同一编辑窗口，不再固定叠加第二个 500ms 等待。手动保存先立即提交本地，再尝试同步到服务端。
- 只有内容、布局、连线、名称或视角变化标记为待保存；选择状态、测量状态、菜单和主题变化不单独生成内容版本。
- 显式新建、切换和导入等操作必须保留原画布待保存内容并绑定正确身份。延续当前“清空画布开启空白项目”的行为；删除当前项目全部节点则作为空数组更新原项目。
- 页面隐藏或离开时尽力提交，但不以卸载事件作为主要持久化机制。尚未完成本地事务的编辑可能在强制关闭时丢失，界面不得提前显示已保存。

### 服务端同步协议

- 使用稳定画布 ID 的保存协议，首次创建与后续更新都携带请求 ID、预期服务端版本及完整快照。客户端本地版本用于对应确认，服务端版本用于并发控制。
- 新画布以预期版本 0 创建；已有画布只有预期版本匹配才更新。每次接受内容写入后递增服务端版本并返回画布 ID、请求 ID 和新版本。
- 服务端事务内同时提交画布内容、版本和幂等回执。以画布 ID 与请求 ID 唯一标识操作，并保存请求内容摘要；相同请求重放返回原确认，不重复创建、不增加版本。
- 幂等回执检查先于版本冲突判断。相同请求 ID 携带不同内容必须拒绝，不能作为重试覆盖原结果。
- HTTP 成功、业务成功且响应身份匹配后才能确认。确认只推进该操作对应的本地版本；更新版本尚未确认时仍显示待同步。
- 首次创建响应丢失时，重启后重放相同持久化请求；确认后再发送期间产生的新修改。不得为每次重试生成新画布 ID 或新请求 ID。
- 数据库增补画布版本、幂等回执及删除标记，并为历史画布初始化版本。迁移必须保留既有画布数据，具备重复执行安全性。
- 所有现有画布写入入口都接入同一版本维护逻辑。旧的无版本写入不能绕过冲突控制；产品内调用方随协议一起迁移，未提供所需字段的写入返回明确校验错误。读取与项目列表保留现有业务字段并增加版本。
- 项目删除保留服务端删除标记并使旧更新失效，项目列表不展示已删除记录；旧客户端不得用“找不到就创建”复活同 ID。用户选择另存副本时生成新 ID。

### 重试、冲突与状态

- 每张画布最多一个未确认操作；不同画布独立调度，全局默认同时最多两张画布同步。任一画布失败不阻塞其余画布。
- 网络错误、请求超时和服务端临时失败采用带抖动的指数退避，起始约 1s、上限约 30s；无网络时暂停，启动、恢复网络和手动保存可触发重试。限流遵循服务端等待提示。
- 校验失败、权限失败、已删除和版本冲突暂停该画布自动重试并明确提示。草稿保留，修改有效内容或显式处理问题后恢复；无效名称不得循环发送相同错误请求。
- 多标签页共享 IndexedDB 时，以事务原子校验草稿本地版本，防止陈旧标签页覆写更新草稿；冲突编辑保留为恢复副本并提示。跨标签页重复发送相同待同步操作由服务端幂等兜底，不依赖页面内布尔锁。
- 服务端版本冲突时保存双方内容，默认不自动覆盖。首版提供“采用服务端版本”和“将本地内容另存为新画布”；采用服务端版本前保留本地恢复副本。不实现自动合并或强制覆盖。
- 显示“保存中”“已保存到本地，待同步”“同步中”“已同步”“本地保存失败”“同步失败/冲突”。只有最新本地修改获得服务端确认才显示已同步。
- IndexedDB 不可用、配额不足、升级被其他标签页阻塞时提供明确提示和重试/导出入口。内存内容保留；本次不静默降级为仅服务端保存，也不误报本地成功。
- 网络恢复指示只是一次重试信号，实际 API 响应决定是否同步成功。界面恢复后的状态从持久化版本和队列推导，不把上次显示文字当作事实。

## Testing Decisions

- 主要验收边界升级为“浏览器真实编辑 → 真实 IndexedDB → 真实应用 API → 隔离 SQLite 读回”。优先在该边界证明用户行为和最终存储结果，不能用 localStorage 或内存对象模拟 IndexedDB 来代替全部验收。
- 使用独立浏览器配置和临时数据库，测试不能写入开发者现有画布。清除本地缓存后从服务端重开，确认新增、编辑、连线、重命名、视角和删除最后一个节点确实进入数据库。
- 在真实浏览器中准备旧 localStorage 草稿，验证成功迁移、再次启动不重复迁移、迁移中断可重试、损坏数据保留、已有 IndexedDB 新草稿不被覆盖。
- 断网编辑并等待“已保存到本地”，刷新编辑器后恢复全部修改；恢复网络后确认 SQLite 最终内容。无需承诺浏览器未缓存应用资源时能在完全离线环境重新加载整个应用外壳，测试须区分 API 断网与静态资源加载。
- 在服务端事务已提交后丢弃响应，再刷新并重试，断言只有一个项目、确认版本不重复递增，且较新的编辑最终保存。
- 控制请求延迟，覆盖保存中继续编辑、手动保存重入、切换画布、切换回来、旧响应迟到以及一张画布永久失败但另一张成功。
- 使用两个标签页验证陈旧本地版本不会静默覆盖；模拟远端更新或删除，验证版本冲突和删除不会导致数据丢失或项目复活。
- 对事务失败、配额错误、数据库打开失败和升级阻塞进行故障注入，断言原内容可恢复且没有虚假成功状态。
- 下层仅保留有价值的快速测试：合并窗口、事务提交确认、版本推进、退避调度、请求重放和 SQL 原子写入。断言外部结果，不断言私有队列结构。
- 复用现有画布 store、草稿与同步协调器测试的组织方式，以及生成任务测试中的独立数据库和故障恢复模式。现有 mock fetch 到 SQLite 的回归测试继续保留，但不视为真实 HTTP 与 IndexedDB 验收。
- 若项目尚无浏览器测试运行器，实施时增加一个最小浏览器测试入口；不为每个组件建立独立测试框架。类型检查、相关测试和真实浏览器验收均须完成后才能宣称迁移完成。

## Out of Scope

- 实时多人协作、CRDT、自动内容合并和任意版本强制覆盖。
- 完整编辑历史、逐操作永久日志、无限草稿版本历史。
- 浏览器数据被清理、磁盘损坏或本地事务提交前强制关页后的无损保证。
- 完整 PWA 离线应用外壳、Service Worker 后台同步、浏览器关闭后仍继续上传。
- 图片/视频二进制缓存迁移、平台连接设置、模型调用和生成任务恢复存储迁移。
- 替换服务端 SQLite、第三方同步服务、登录或权限体系重建。
- 全面重做项目列表或旧工具栏；仅增加保存状态、错误恢复和必要的副本入口。

## Further Notes

- 本版取代此前同一规格中的基础自动保存范围：持久化待同步队列、旧草稿迁移、幂等创建、服务端版本校验和保存状态现在纳入实现范围。
- 500ms 合并、2s 非拖拽最大等待、两张画布并发及退避参数为本规格提出的工程默认值，不代表用户逐项指定；可根据性能验收调整，不能削弱数据一致性要求。
- 当前工作区只有 localStorage 草稿和内存同步队列的初步修复。IndexedDB 迁移、持久队列、服务端幂等/版本/删除标记与新的浏览器验收尚未实现；前一轮通过的 57 项测试不证明本规格完成。
- 已发起测试边界核对，主边界为真实浏览器、IndexedDB、API 和 SQLite；未回复不记为用户明确认可。Status 表示规格可用于执行，不表示功能已交付。
- 本轮仅发布规格，不修改实现、不拆票、不启动迁移。
