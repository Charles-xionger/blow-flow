# 02: 断网与刷新后恢复同步

**What to build:** 创作者断网时继续编辑，已完成本地提交的修改刷新后仍可恢复；网络恢复后自动补传。即使服务端已写入但响应丢失，也不会重复创建项目或回退新内容。

**Blocked by:** 01 — IndexedDB → 服务端自动保存基础链路。

Status: ready-for-agent

## Acceptance criteria

- [x] 启动从 IndexedDB 重建草稿、未确认操作和保存状态，不依赖上次页面内存或显示文字；本地待同步内容优先保留，不被较旧服务端快照替换。
- [x] 每张画布最多一个未确认操作；请求已经发送后，即使有新编辑也不修改其请求 ID、内容和预期版本。先确认原操作，再基于返回版本提交新快照。
- [x] 服务端已提交但响应丢失时，刷新后重放原持久化操作；创建和更新都复用原请求 ID，确认事务不删除期间产生的新版本。
- [x] 断网暂停请求；启动、网络恢复和手动保存可唤醒队列。网络状态只是重试信号，实际响应决定同步成功。
- [x] 网络错误、请求超时和临时服务端错误采用带抖动的指数退避，起始约 1s、上限约 30s；限流遵循服务端等待提示，重启后不形成密集重试。
- [x] 校验、权限、版本冲突和已删除错误暂停对应画布自动重试，保留内容并提示。修正无效内容可继续保存；未知提交结果不能通过丢弃原请求并发送新请求规避核实。
- [x] 手动保存期间继续编辑时，确认仅对应已提交版本，较新的编辑保持待同步；自动保存和手动保存重入不会并行创建或发送乱序更新。
- [x] 页面隐藏或离开时尽力提前提交，但普通本地提交和恢复不依赖卸载回调；本地事务未完成时不承诺强制关闭后无损。
- [x] 真实浏览器测试：仅断开 API 网络，编辑并等待本地已保存，刷新恢复全部内容；恢复 API 后确认 SQLite 最新快照，并在无本地缓存环境读回。
- [x] 故障测试在服务端提交后丢弃响应，刷新再补传，确认仅一个项目且原操作不会重复递增服务端版本；覆盖确认前又产生新修改的情形。
- [x] 验证请求超时、退避、永久错误暂停和旧响应迟到，不只验证请求发出；相关回归测试与类型检查通过。
