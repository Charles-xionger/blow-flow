# 03: 安全迁移旧 localStorage 草稿

**What to build:** 用户升级后自动恢复原有草稿到 IndexedDB，不重复导入，不覆盖更晚创作；旧草稿与服务端不同步时，可保留副本并选择安全恢复方式。

**Blocked by:** 01 — IndexedDB → 服务端自动保存基础链路。

Status: ready-for-agent

## Acceptance criteria

- [ ] 首次初始化识别并验证旧 canvas-storage envelope 和画布结构；迁移在默认空状态写入之前完成，已有画布保留原 ID，无 ID 草稿获得稳定新 ID。
- [ ] 导入记录与迁移完成标记同事务提交，事务中断后可重新执行；再次启动不重复导入、重复创建或覆盖已有 IndexedDB 草稿。
- [ ] 迁移成功后停止写旧画布键，保留旧原文作为备份；不迁移主题、生成任务恢复记录及平台设置等独立数据。
- [ ] 同 ID 已有 IndexedDB 草稿时不覆盖；内容不一致且无法确定新旧时保存可访问的独立恢复副本，不用客户端时间决定覆盖关系。
- [ ] 无可信服务端版本的旧草稿不能直接上传覆盖已有项目。联网读取并比较持久化字段：相同则建立版本基线；不同则保留双方内容并提示选择。离线时允许恢复可读草稿，暂停未经核对的覆盖请求。
- [ ] 用户可以采用服务端版本或将本地内容另存新画布；采用服务端版本前仍保留本地恢复副本，另存使用新 ID 并经自动保存链路入库。为 04 留出可复用的恢复入口，不实现强制覆盖。
- [ ] 损坏原文、验证失败或迁移事务失败不删除原数据，展示迁移失败及重试/导出恢复入口，不误报迁移成功。
- [ ] 迁移和恢复副本不触发新的模型生成请求；副本遵守已有复制画布时的生成任务身份处理规则。
- [ ] 真实浏览器预置旧草稿，验证首次迁移、重复启动、迁移中断再试、损坏数据和与既有 IndexedDB 记录冲突；原文备份均保留。
- [ ] 使用真实 API 与隔离 SQLite 验证旧草稿与服务端相同及不同时的行为，确认未经用户选择不会覆盖远端；另存副本确实可以从服务端独立读回。
- [ ] 正常在线迁移可独立完成，不依赖 02 的自动离线重试；相关回归测试及类型检查通过。

## Scope notes

本票包含迁移所需的错误提示与恢复选择。IndexedDB 全局不可用、配额不足和升级阻塞等完整故障体验由 05 补齐，多标签页及一般远端编辑冲突由 04 补齐。
