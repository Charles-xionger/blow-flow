# 03: 安全迁移旧 localStorage 草稿

**What to build:** 用户升级后自动恢复原有草稿到 IndexedDB，不重复导入，不覆盖更晚创作；旧草稿与服务端不同步时，可保留副本并选择安全恢复方式。

**Blocked by:** 01 — IndexedDB → 服务端自动保存基础链路。

Status: ready-for-agent

## Acceptance criteria

- [x] 首次初始化识别并验证旧 canvas-storage envelope 和画布结构；迁移在默认空状态写入之前完成，已有画布保留原 ID，无 ID 草稿获得稳定新 ID。
- [x] 导入记录与迁移完成标记同事务提交，事务中断后可重新执行；再次启动不重复导入、重复创建或覆盖已有 IndexedDB 草稿。
- [x] 迁移成功后停止写旧画布键，保留旧原文作为备份；不迁移主题、生成任务恢复记录及平台设置等独立数据。
- [x] 同 ID 已有 IndexedDB 草稿时不覆盖；内容不一致且无法确定新旧时保存可访问的独立恢复副本，不用客户端时间决定覆盖关系。
- [x] 无可信服务端版本的旧草稿不能直接上传覆盖已有项目。联网读取并比较持久化字段：相同则建立版本基线；不同则保留双方内容并提示选择。离线时允许恢复可读草稿，暂停未经核对的覆盖请求。
- [x] 用户可以采用服务端版本或将本地内容另存新画布；采用服务端版本前仍保留本地恢复副本，另存使用新 ID 并经自动保存链路入库。为 04 留出可复用的恢复入口，不实现强制覆盖。
- [x] 损坏原文、验证失败或迁移事务失败不删除原数据，展示迁移失败及重试/导出恢复入口，不误报迁移成功。
- [x] 迁移和恢复副本不触发新的模型生成请求；副本遵守已有复制画布时的生成任务身份处理规则。
- [x] 真实浏览器预置旧草稿，验证首次迁移、重复启动、迁移中断再试、损坏数据和与既有 IndexedDB 记录冲突；原文备份均保留。
- [x] 使用真实 API 与隔离 SQLite 验证旧草稿与服务端相同及不同时的行为，确认未经用户选择不会覆盖远端；另存副本确实可以从服务端独立读回。
- [x] 正常在线迁移可独立完成，不依赖 02 的自动离线重试；相关回归测试及类型检查通过。

## Scope notes

本票包含迁移所需的错误提示与恢复选择。IndexedDB 全局不可用、配额不足和升级阻塞等完整故障体验由 05 补齐，多标签页及一般远端编辑冲突由 04 补齐。


## Comments

2026-11-01：任务 03 已实现。初始化先验证并迁入旧 `canvas-storage` envelope，导入与完成标记同事务提交；无 ID 草稿在本浏览器预留随机稳定 ID，避免相同内容在不同浏览器中碰撞。原文始终保留，主题和独立生成恢复记录不迁移。同 ID 的 IndexedDB 内容不会被覆盖，不同内容保存为可访问的恢复副本。

旧项目没有可信服务端基线时暂停写请求；读取并比较持久化字段，相同则建立版本基线，不同则提示采用服务端版本或另存新画布。采用前原子保存本地恢复副本，恢复期间暂停编辑，确保最后的修改进入备份。副本使用新的画布、节点和连线身份，并清除生成任务关联；迁入及采用的节点仅恢复已有任务查询，不自动提交待确认生成请求，显式发起生成后恢复该节点的正常行为。迁移失败提供重试和原文下载。

验证：`pnpm test` 全部 88 项通过；`pnpm test:browser` 全部 19 项通过（其中 11 项迁移验收）；`pnpm typecheck` 与修改的核心 TypeScript 模块、恢复组件和浏览器测试 ESLint 检查通过。浏览器使用真实 IndexedDB、真实 API 与隔离 SQLite，覆盖首次迁移、重启去重、事务中断回滚重试、损坏原文导出、已有本地草稿冲突、离线恢复、远端相同/不同、两种恢复选择、独立副本读回及不提交生成请求。恢复副本重启用例等待 URL 切换完成后刷新，连续重跑 3 次通过。

### Standards

以 `7589206` 为基准审查。初审对直接检查 IndexedDB 提出疑问；复核确认本规格明确授权真实存储及迁移标记的验收边界，因此撤回该意见。无剩余规范或 ADR 违规。

### Spec

初审发现 2 项 P1：恢复读取期间的编辑可能遗漏于备份；采用服务端版本时，服务端独有节点可能自动提交待确认生成请求。均已补充先失败后通过的回归测试并修复，复核无剩余任务 03 阻塞项。

审查结果：Standards 0 项未解决；Spec 0 项未解决。完整多标签页、通用远端冲突处理及 IndexedDB 全局故障体验仍分别属于任务 04、05。
