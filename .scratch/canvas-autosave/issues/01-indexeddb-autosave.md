# 01: IndexedDB → 服务端自动保存基础链路

**What to build:** 创作者新增或编辑画布后，先可靠保存到 IndexedDB，再自动写入服务端 SQLite；界面准确区分本地保存与服务端同步。保存按钮和快捷键使用同一链路。

**Blocked by:** None (can start immediately).

Status: ready-for-agent

## Acceptance criteria

- [x] 新画布首次需要保存时生成稳定 ID；本地和服务端使用同一 ID。已有服务端画布保留原 ID。空白新画布不自动创建项目。
- [x] IndexedDB 使用版本化结构保存草稿、待同步操作和迁移元数据；一次事务同时提交快照、本地递增版本和待同步状态，事务完成后才显示本地保存成功。
- [x] 草稿记录最后确认的本地及服务端版本；待同步操作持久化请求 ID、画布 ID、发送快照、本地版本和预期服务端版本。发送后的操作不可变，新编辑保留为下一待发送版本。
- [x] 节点新增、编辑、移动、删除，连线增删、名称及视角变化均可自动保存；删除最后一个节点提交空数组。选择、测量、菜单、主题变化不单独生成内容版本。
- [x] 约 500ms 合并编辑，非拖拽持续编辑最长约 2s 提交本地；拖拽中合并，结束后提交最终位置。本地提交后直接安排同步，不额外叠加固定防抖等待。
- [x] 顶部保存按钮、快捷键与自动保存共用协调器；手动保存立即提交本地并等待该版本的服务端确认，不因本地写入完成而弹出服务端保存成功。
- [x] 初始化先恢复 IndexedDB，再核对服务端；恢复期间禁止默认空画布触发写入，SSR 不访问浏览器存储。本地待同步内容不会被服务端读取结果直接覆盖。
- [x] 服务端保存请求携带稳定画布 ID、请求 ID、预期版本和快照；新建预期版本为 0，更新必须匹配当前版本，否则返回明确冲突。历史画布初始化版本，数据库升级保留原数据且可重复执行。
- [x] 服务端在同一事务内写入画布、递增版本和幂等回执；先查回执再校验版本。同请求同内容返回原确认且不重复创建或增加版本，同请求不同内容拒绝。
- [x] 响应包含可核对的画布 ID、请求 ID、服务端版本；只有 HTTP 与业务均成功且身份匹配才确认对应本地版本，旧响应不能把更晚修改标为已同步。
- [x] 当前实际使用的画布写入入口均迁移至版本协议，无版本写入不能绕过控制；读取及列表保留业务字段并增加版本，保持现有新建、打开和导入功能可用。新协议允许返回冲突并保留内容，完整冲突处理由后续任务补齐。
- [x] 显示保存中、本地已保存待同步、同步中、已同步及基本错误状态；未确认的最新版本不能显示已同步。本地失败不静默退回仅服务端写入。
- [x] 保留旧 localStorage 草稿原文，为 03 提供迁移入口；本票不删除或覆盖旧草稿。主题和生成任务等独立存储不迁移，不重新提交生成任务。
- [x] 建立最小真实浏览器测试入口，使用独立浏览器配置和临时 SQLite：新增节点经真实 IndexedDB、真实 API 落库，清除本地缓存后仍能从服务端读回；覆盖修改和删除最后一个节点。
- [x] 验证服务端请求重放、版本冲突和事务回滚，以及本地事务完成前不得显示成功；相关既有回归测试及类型检查通过。

## Scope notes

以已提交的基础自动保存修复为起点，复用现有 store 操作与保存入口。刷新后的队列恢复和自动退避属于 02，旧数据迁移属于 03，多画布故障隔离和冲突处理属于 04，详细本地故障恢复属于 05。本票交付正常在线路径及后续任务可复用的持久化协议，不宣称完整离线能力。
