# 02: 推送中断时自动补齐状态并降级轮询

**What to build:** 画布在 SSE 断线、页面刷新或重新打开后恢复生成任务最新状态；推送持续不可用时显示连接提示并每 10 秒轮询，推送恢复后停止轮询。用户能够看到断线期间完成的最终图片，继续查询与重试保存仍作用于原任务。

**Blocked by:** 01: 画布通过共享 SSE 接收生成任务状态与最终图片。

**Status:** ready-for-agent

- [ ] 断线重连同步数据库中的最新公开状态及结果，不依赖逐条事件回放；刷新或重新打开画布后从已保存的任务关联恢复订阅。
- [ ] 明确并记录“SSE 持续不可用”的有限时间或连续失败判定规则，并用可控制时钟的测试覆盖；连接挂起或失去活性时也能进入恢复流程，不无限等待。
- [ ] 达到降级条件后显示连接提示，按每 10 秒的节奏查询需要跟踪的任务；不会同时保留原来的每节点 2 秒轮询。
- [ ] 降级期间继续尝试恢复 SSE；确认恢复推送并完成最新状态同步后，停止降级轮询并清除连接提示，避免反复创建重复计时器或连接。
- [ ] 断线期间任务成功、失败或 OSS 转存状态变化，重连或降级查询后均能正确展示；不能在生成成功但转存尚未完成时过早停止跟踪。
- [ ] 推送与 HTTP 查询响应交错或迟到时不会让已展示状态回退；旧任务、已删除节点及已切换画布的响应不能影响当前展示。
- [ ] 继续查询和重试保存仍通过 HTTP 提交，并重新激活原任务的状态跟踪；通知失败本身不能触发重新生成或重复付费提交。
- [ ] 页面卸载、画布切换后释放重连、轮询和活性检测资源；后续重新进入画布仍能正常恢复。
- [ ] 自动化验证覆盖初次连接失败、持续断线、断线期间完成、重连补齐、降级后恢复、迟到响应与资源清理，并验证继续查询和重试保存的完整展示流程。
