# 03: RunningHub 使用 WebSocket 优先跟踪，HTTP 查询兜底

**What to build:** 按 ADR 0003，由 worker 使用 RunningHub 返回的 `netWssUrl` 优先跟踪生成任务。完成信号触发 HTTP 结果查询，经确认后持久化状态并按现有流程转存 OSS，让用户通过已有公开任务查询看到状态与最终图片；SSE 接入完成后自然使用同一份持久化状态。WebSocket 不可用或遗漏完成事件时，通过原平台任务 ID 查询恢复，不重新提交生成任务。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 结合官方进度示例核实当前国际站工作流的实际地址获取方式、事件格式、完成信号及连接行为，记录脱敏验证证据与可复用测试样本；不将示例视为可靠投递或地址长期有效的保证。
- [ ] worker 从平台响应获取 `netWssUrl` 并建立后端 WebSocket 跟踪；正常连接以 WebSocket 通知优先，同时保留有界的 HTTP 兜底检查以发现遗漏的完成事件。
- [ ] 排队尚无地址、连接失败、断线、地址失效或完成事件缺失时，使用原平台任务 ID 查询；查询仍在运行时可以重新取得可用地址并恢复跟踪。
- [ ] worker 重启后从持久化平台任务 ID 恢复查询与跟踪，不依赖内存连接或旧地址有效，也不重新提交生成任务。
- [ ] WebSocket 完成信号只触发 HTTP 结果确认；仅凭消息不直接宣布生成成功或写入未经确认的产物。确认结果后沿用公开状态持久化、OSS 转存及保存失败重试流程。
- [ ] 重复完成信号、HTTP 兜底与 WebSocket 通知并发、旧连接迟到消息不会导致重复提交、覆盖较新状态或绕过 worker 的租约与写入保护。
- [ ] 保持 ADR 0002 的待核实、查询期限、等待超时、连接并发占用、删除节点后继续跟踪已提交任务等语义；连接等待不阻塞其他可执行任务，任务停止跟踪或 worker 退出时释放连接资源。
- [ ] 平台鉴权地址与凭据仅限后端使用，不进入公开任务响应、SSE 或前端可见错误；新增诊断信息遵守既有脱敏边界。
- [ ] 自动化验证覆盖正常完成、排队无地址、连接失败、断线、完成事件缺失、重复事件与 worker 重启，并断言同一平台任务不会重新提交；通过公开任务查询验证最终状态和 OSS 图片结果，无需等待 SSE 工单完成。

平台实际完成到本地落库的等待不计入 ADR 0003 的 1 秒页面通知目标。本工单可与画布 SSE 接入并行，复用已有持久化任务与公开查询契约。
