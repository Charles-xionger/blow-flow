# 01: 画布通过共享 SSE 接收生成任务状态与最终图片

**What to build:** 按 ADR 0003，画布通过一条共享 SSE 连接接收生成任务的公开状态、结果保存状态与最终图片，替代正常连接时按节点轮询。数据库仍是状态依据，Web 与 worker 独立进程共享现有 SQLite。首次连接取得最新状态，不要求回放中间状态。生成、继续查询和重试保存等操作仍通过 HTTP 提交。沿用 ADR 0002 的任务恢复、节点关联和结果保存语义。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 浏览器使用 `@microsoft/fetch-event-source`；一个画布页面的多个生成任务共享一条连接，新增任务可加入订阅，任务关联变化后订阅随之更新。
- [ ] 首次连接向页面同步订阅任务的最新公开状态及结果；状态、保存状态或产物变化均能更新对应节点，最终展示已转存 OSS 的图片。
- [ ] 同一个 Web 进程的连接共享一个检查器，每 500ms 批量检查当前订阅的任务；多个连接订阅相同任务时不重复为该任务建立检查循环。
- [ ] 初始同步之外，仅在公开状态或结果变化时推送任务更新；租约、查询调度时间等内部字段变化不触发无意义更新。
- [ ] 无订阅时停止数据库周期检查；页面卸载、画布切换或连接关闭后释放相应订阅和资源。
- [ ] 正常网络下，以状态持久化后 1 秒内通知在线页面为目标；通过独立 Web 与 worker 进程共享 SQLite 的集成场景验证并记录测量结果，平台完成到本地落库的时间不计入该目标。
- [ ] 沿用公开任务数据边界，不通过 SSE 暴露平台凭据、鉴权地址或私有诊断信息。
- [ ] 旧任务迟到的结果不会覆盖节点最近一次生成，删除节点或切换画布后收到的更新不会重新创建节点或修改其他画布；草稿保存后的画布标识变化不会丢失原任务跟踪。
- [ ] 自动化验证覆盖初始快照、状态与最终图片推送、多任务共享连接、共享检查器、无变化不推送及订阅清理；保持现有 HTTP 操作和任务恢复验证通过。

本次范围为单机部署下的任务状态与最终图片；不包含多人协作、生成百分比、预览图、Redis 或任务状态事件的生产者／消费者机制。
