# 生成任务通知验收记录

依据 ADR 0003，实现三个已确认工单。代码审查基线为 `7d61b4ec004b96ef8f65f4cba55afa9c85ff5d66`。

## 运行行为

- 每个画布页面共享一条 POST SSE；订阅任务集合变化时关闭旧连接并重新取得快照。操作仍走既有 HTTP 接口。
- Web 进程按数据库连接共享检查器，每 500ms 批量查询去重后的订阅任务，无订阅时停止。初始快照之后只发送公开状态版本变化，另每 10 秒发送心跳。慢客户端最多积压 64 个事件后关闭连接，靠最新快照恢复。
- SQLite 增量迁移添加公开状态版本号；状态、保存状态、产物、错误或查询期限变化时原子递增。内部租约和查询调度更新不触发通知。客户端按版本拒绝迟到结果。
- 15 秒未建立有效快照或持续连接失败后降级，每 10 秒查询。连接失败后每 3 秒尝试恢复；已连接但 25 秒没有消息则重连并降级。恢复快照后取消轮询。单次 HTTP 兜底查询最多等待 10 秒。
- RunningHub WebSocket 只作为查询提示，完成后用原平台任务 ID 确认结果。健康连接的兜底查询间隔为配置轮询间隔与 30 秒的较大值；未连接时使用原配置间隔。握手失败不会触发紧密查询循环。超时与 worker 租约语义保留。
- Web 与 worker 继续分别启动，使用相同 SQLite 路径；无需新增服务或 Redis。新增连接依赖已记录在包清单及锁文件中。

## 验证证据

- 类型检查、修改范围 ESLint、生产构建通过。
- 最终全量自动化测试 51/51 通过，包含 WebSocket 握手失败间隔与继续查询／重试保存组合场景。
- 独立 worker 进程与 Web 共享 SQLite：最终 OSS 结果落库后 499ms 到达 SSE。
- 生产 Next.js HTTP 冒烟：页面返回 200，SSE 收到初始快照；HTTP 取消排队任务后 503ms 收到状态更新。
- 真实国际站 Krea2：512×512 最小图片，一次提交，一条 WebSocket 连接，生成与 OSS 保存均成功；整个验证约 47.9 秒。
- 真实响应中 create 返回 code 0 和 netWssUrl；运行中 outputs 返回 code 804 和 netWssUrl；完成后 outputs 返回 code 0 及产物数组。
- 观察到事件类型：progress_state、executing、status、progress、executed、execution_success。完成事件触发 HTTP 结果确认。自动化测试只保留完成信号与查询响应的最小脱敏样本，不保存鉴权地址或平台凭据。
- 官方参考：https://www.runninghub.ai/runninghub-api-doc-en/doc-8287471 。真实国际站验证独立于示例，不假设通知可靠投递。
