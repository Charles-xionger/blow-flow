# 分镜生成分阶段执行设计

Status: proposed

2026-11-07。依据用户反馈：单次请求超过 180 秒仍停留在模型思考阶段，不能继续依赖一次完整输出。本文为实现方案，尚未修改运行逻辑。

## 已确认的问题

当前 `lib/script/service.ts` 对一次任务只执行一次 `streamText(scriptPrompt(input))`，将全部要求交给模型，共用 180 秒定时器，结束后统一校验。`lib/script/storyboard.ts` 同时要求镜头规划、全部镜头细节、角色／场景／道具以及完整视频提示词。任务只保存一段原文，没有独立阶段产物或重做失败部分的检查点。

截图显示最后阶段为“模型思考中，等待正文”，不是传输正文缓慢。分阶段能缩小请求、隔离失败，但不能保证首个请求不再长时间思考。首段正文等待与整次请求时限必须分别处理，不能靠延长总时限或制造进度百分比解决。

## 产品行为

画布始终只创建一个分镜节点。一键生成默认连续执行后续文本阶段，不增加逐阶段人工确认。用户可停止；关闭页面不停止后台任务。每阶段产物独立保存，已完成部分立即可见，后续失败不会清空前面的工作。

默认 60 秒、最多 5 镜、每镜最多 15 秒；120 秒至少 8 镜。数量上限与总时长在提交前校验。不会自动批量生图或生视频，不会自行切换模型或自动重试付费请求。

## 执行顺序与产物

| 阶段 | 输入 | 输出 | 执行方式 |
| --- | --- | --- | --- |
| 1. 规划镜头 | 原故事、参考、创作要求、时长和数量约束 | 精简故事摘要、固定镜头 ID、顺序、时长、每镜一句叙事目的及主要动作、所涉资产名称 | 一次小规模模型请求 |
| 2. 整理资产 | 规划结果、参考中相关设定 | 去重后的角色、场景、道具；稳定资产 ID、名称、视觉描述及镜头关联 | 一次独立模型请求；无新增资产也记录完成 |
| 3. 完善镜头 | 全局摘要、固定规划、相关资产设定、相邻镜头概要 | 每镜画面、景别、光影、对白、声音、运镜；保留既定镜号、时长和资产 ID | 每批最多 2 镜；最多 2 批并发 |
| 4. 组装提示词 | 已完成镜头、关联资产、创作风格 | 独立可编辑的视频提示词 | 本地模板组装，默认不调用模型 |

以 5 镜为例，初始配置为 1 次规划 + 1 次资产整理 + 3 次镜头细化，共 5 次小请求。调用次数与潜在总费用增加，不能承诺总时长一定下降；收益是更早展示可用结果、减少重复生成和缩小重试范围。并发只用于互不依赖的镜头批次，不让资产整理与依赖其结果的镜头细化抢跑。

规划阶段不生成对白全文、镜头技术细节或视频提示词；资产阶段不重写镜头；细化阶段禁止增加镜头、改变镜头 ID、调整计划时长或重新定义资产。资产缺失时返回明确问题，不能悄悄发明另一个角色版本。组装提示词只使用已完成内容，不补造故事。

镜头时长由规划产物明确给出，服务端校验数量、单镜上限与总和；不通过就停在规划阶段，提供“重试规划”，不把错误规划送往下游。批次结果必须恰好包含该批预定镜头，重复、遗漏、未知 ID 或空必填字段均视为未完成。

## 结构化产物与流式展示

新流程使用独立结构化产物作为执行依据，Markdown 仅用于兼容和导出，不再靠大段 Markdown 标题判断镜头身份和恢复位置。每个短请求采用明确的 JSON schema 约定；不能假定所有模型支持供应商级结构化输出，统一层传输后由应用校验。

原始流只更新当前阶段草稿，未通过校验的半段 JSON 不进入已完成产物，也不触发下游请求。规划完成后立即在列表显示镜号、时长、动作概要；每批细化完成后填入对应行。进行中的批次可查看原始文本草稿，但不能把“收到字符”标成“镜头完成”。

视频提示词作为可编辑产物保存。人工修改后的提示词不会被自动组装覆盖；“重新组装”必须是显式操作。字段更改需要重新组装时显示过期待更新提示。

## 任务、检查点与幂等

新增独立的分镜流水线模块，例如 `lib/script/pipeline/`，对调用方暴露 start、read、stop、resume、retryStep；不把阶段编排散落到节点组件、SSE 或模型 Adapter 中。继续通过 `lib/ai-services/text` 通用层调用模型，不直连 Ark。

持久化分为：

- 流程：任务 ID、创建请求 ID、画布和唯一结果节点 ID、输入快照／摘要哈希、模型、状态、修订号。
- 阶段步骤：步骤 ID、阶段、批次的镜头 ID、依赖产物版本、状态、尝试次数、lease、执行截止时间、公开错误码。
- 尝试记录：请求身份、起止时间、首次正文时间、传输状态、原始流草稿及失败类型；不保存凭据，不向前端暴露内部思考内容。
- 已提交产物：规划、资产目录、逐镜头详情、视频提示词，各自有版本与对应输入哈希。

只有通过校验的结果能原子提交为产物并将步骤置为完成。状态提交使用 lease 和尝试 ID 做写入栅栏，旧执行者的迟到输出不能覆盖新尝试。

客户端重复提交同一请求返回同一流程与结果节点。用户主动“全部重新生成”才创建新流程和新结果节点；“继续／重试失败步骤”复用原结果节点和已完成产物。重试请求也带幂等 ID，双击不能重复调用模型。

重启后保留检查点，过期执行标为中断；用户点击继续后，已完成步骤不重做，只调度未完成的步骤。无法判定供应商是否仍执行的旧尝试标记中断，不自动发送替代请求；明确告知重试可能产生新费用。

## 失败、停止与编辑

状态分为 queued、running、completed、failed、stopped、interrupted，以及因依赖改变产生的 stale。UI 的完成计数只统计已校验、已提交产物。

- 规划失败：没有有效规划，不能开始后续阶段，显示“重试规划”。
- 资产失败：镜头规划保持可见，显示“重试资产整理”。
- 某批镜头失败：其他已在执行的独立批次可结束，停止领取新批次；保留成功镜头，显示失败镜号和“继续未完成镜头”。
- 停止：停止调度新步骤，取消当前请求；已完成产物与未完成草稿均保留。
- 编辑上游：增加输入版本，使依赖该版本的未完成请求失效。原结果保留为过期内容，绝不自动付费重跑。
- 编辑镜头规划／时长：只失效受影响镜头及其提示词；修改全局风格影响全部镜头；修改某个资产只影响引用它的镜头。
- 删除结果节点：不复活节点，取消后续调度；已完成产物仍保留在任务记录。

活动请求中的目标行暂不可编辑；已完成行可以编辑，版本栅栏保证迟到结果不覆盖手工修改。

## 超时与进度

取消“整个流程共用 180 秒”的控制方式，改为每次尝试独立预算，并区分连接、首段正文、正文停滞和整次尝试超时。初始候选值（须实际测量后调整）：连接 20 秒、首段正文 60 秒、正文停滞 30 秒、每次尝试总时长 120 秒。首段正文定时器不能被思考事件不断续期；连接超时不包含首段正文等待。

流程总执行预算独立配置，初始建议 10 分钟，耗尽后停止调度并保留检查点。不能通过换阶段重置同一请求的总预算。每次尝试的超时由统一 AbortSignal 向模型 Adapter 传播；超时不自动重试。

以上预算是设计起点，不是已经验证的模型 SLA。拆阶段后首段正文仍超时，应提示该阶段和模型情况；评估是否暴露模型推理强度配置需要先查供应商能力，不能假定当前模型支持关闭思考。

进度使用事实：规划镜头中、镜头规划完成 5/5、资产完成 6/6、镜头细化 2/5、提示词就绪 2/5；另外显示当前阶段的“连接／等待正文／正文输出”与已等待时间。不显示无法测量的 3% 或整体生成百分比。

## 同步与数据库约束

查询与 SSE 保持只读。模型请求和等待绝不置于 SQLite 写事务中。流式草稿按时间或字数合并写入，避免逐 token 落库；停止和完成前尽力提交已收到草稿，并遵守写入栅栏。

阶段产物优先写独立产物表，小事务提交；画布只在创建分镜节点以及提交展示快照时更新，不逐 token 重写整张画布和撤销历史。UI 复用一条流程通知，画布图结构继续走现有版本同步，不让每个镜头各自刷新画布。

## 落地顺序与影响文件

1. 新增阶段模型、产物存储、租约／依赖版本与恢复调度：`lib/script/pipeline/`；复用现有 worker 生命周期。
2. 将单次大提示词拆为规划、资产、镜头细化三个专用构建器：`lib/script/storyboard.ts` 的输出规则迁入对应模块；提示词组装成为纯函数。
3. `lib/script/service.ts` 对新 board 任务转交流水线；自由创作、写剧本和旧任务保持兼容。
4. `lib/ai-services/text/index.ts` 保留通用模型注入，补充尝试级截止时间／取消信号所需接口；供应商协议留在现有 Adapter。
5. 扩展 `app/api/script/` 的流程读取、继续与重试操作；每项修改沿用 requestId 幂等、租约栅栏与输入校验。
6. `components/nodes/StoryboardNode.tsx` 展示检查点进度、失败镜头、继续按钮和只读草稿；`hooks/useScriptOutput.ts` 与 `lib/script/client.ts` 消费阶段产物通知。
7. 已生成旧文稿不自动拆解或重做；新流程标记协议版本。旧失败任务可显式发起新流程，不能伪造已有检查点。

## 验收场景（本轮只设计，不执行测试）

60 秒最多 5 镜时，先显示有效规划，再逐批补齐详情；最终每镜不超过 15 秒，总和 60 秒。第 2 批失败后，继续操作不得重新调用规划、资产及第 1 批。刷新、双击继续、停止后迟到数据、worker 重启均不重复创建节点或覆盖已完成结果。新旧任务可以共存。模型零正文超时应定位到步骤并保留其他检查点，不退化成整个分镜丢失。

用户此前要求不运行测试；本轮未运行测试，也未调用模型。
