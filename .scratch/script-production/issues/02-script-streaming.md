# 02：真实脚本后台生成与流式展示

Status: resolved

**What to build:** 用户能新建脚本节点，填写文本要求，选择语言模型，看到真实后台流式正文和方案 A 控制台；已收到的正文持久保存，状态可查询。

**Blocked by:** None (can start immediately)

## Acceptance criteria

- [x] 用户可从正式的新建入口创建脚本节点；展示区、工具栏和浮动控制台沿用现有交互分工。
- [x] 控制台参考已选定的方案 A 与 LibTV 布局，具备大输入区、模型选择、展开和运行入口，不带原型切换器或模拟结果。
- [x] 通用文本层提供统一流式契约，接入两个已登记的 Ark 模型并保持 Gemini 兼容；业务入口不包含厂商专用 HTTP 分支。
- [x] 后台服务处理任务，任务创建请求幂等；服务端保证同节点一个活动任务，不同节点独立执行。
- [x] 提交时固定本次文本要求和模型等输入；服务端持久保存任务身份、输入快照、顺序正文和状态，密钥不进入公开数据。
- [x] 前端消费公开任务状态与正文，重复或乱序通知不重复插入文字，最终正文与服务端一致。
- [x] 等待时显示成熟库的粒子动画，正文返回后动画缩到顶部，不显示虚构百分比。
- [x] 失败显示明确状态，不静默重试供应商、不自动换模型；节点不存在时不被任务结果重新创建。
- [x] 此切片可演示一次文本生成从点击到持久完成，不以仅完成适配器、表结构或静态页面作为交付。

## Implementation context

沿用现有通用模型接入和任务幂等／租约／通知模式，文本正文使用自己的结果契约，不伪装为素材 URL。停止和异常恢复的完整交互由 04 补齐；版本管理由 05 补齐。

## Validation boundary

以公开服务行为和真实画布交互作为验收边界，遵循规格的 Testing Decisions。沿用用户“不运行测试”的要求，本任务清单不授权执行自动测试或真实付费模型联调。类型、lint 与静态检查可用于实施反馈；未执行项必须如实报告。

## Answer

已实现正式 `script` 节点、新建入口和方案 A 浮动控制台（大输入区、模型选择、展开、运行、正文与真实状态）。粒子使用按需加载的 tsParticles，仅活动且可见节点运行，24 FPS / 28 粒子，遵循减少动态效果偏好。

`lib/ai-services/text/index.ts` 的 `streamText` 提供统一异步正文流，复用 Ark 连接配置并支持两个已登记 Ark 模型和 Gemini；脚本服务不含厂商 HTTP 分支，不自动重试供应商或切换模型。SQLite `script_tasks` 保留任务身份、规范化输入快照、累计正文和递增修订号；创建幂等、同节点活动任务唯一、执行租约及续约均由服务端保证。独立 `script:worker` 已加入 `dev:all`，关闭页面不终止任务。

公开边界为 `ScriptService.create/get/list/runNext`、`/api/script/tasks`、`/api/script/events`，输入和状态契约见 `lib/script/types.ts`。共享每画布 SSE 通知使用持久正文快照和修订号，重连不会重复追加文本，失败回退为 10 秒查询。任务结果不写整图，不重新创建删除节点；未执行且节点已删除时不调用模型。参考预检、完整停止恢复和版本编辑分别由 03、04、05 延伸这些接口。

验证：`pnpm typecheck` 和全部受影响代码 ESLint 通过，`git diff --check` 通过。遵照用户要求，未写入或运行任何自动测试，未调用真实付费模型；实际供应商流和浏览器视觉交互尚未实测，不能将静态检查视为端到端验收通过。
