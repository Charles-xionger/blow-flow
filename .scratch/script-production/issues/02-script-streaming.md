# 02：真实脚本后台生成与流式展示

Status: ready-for-agent

**What to build:** 用户能新建脚本节点，填写文本要求，选择语言模型，看到真实后台流式正文和方案 A 控制台；已收到的正文持久保存，状态可查询。

**Blocked by:** None (can start immediately)

## Acceptance criteria

- [ ] 用户可从正式的新建入口创建脚本节点；展示区、工具栏和浮动控制台沿用现有交互分工。
- [ ] 控制台参考已选定的方案 A 与 LibTV 布局，具备大输入区、模型选择、展开和运行入口，不带原型切换器或模拟结果。
- [ ] 通用文本层提供统一流式契约，接入两个已登记的 Ark 模型并保持 Gemini 兼容；业务入口不包含厂商专用 HTTP 分支。
- [ ] 后台服务处理任务，任务创建请求幂等；服务端保证同节点一个活动任务，不同节点独立执行。
- [ ] 提交时固定本次文本要求和模型等输入；服务端持久保存任务身份、输入快照、顺序正文和状态，密钥不进入公开数据。
- [ ] 前端消费公开任务状态与正文，重复或乱序通知不重复插入文字，最终正文与服务端一致。
- [ ] 等待时显示成熟库的粒子动画，正文返回后动画缩到顶部，不显示虚构百分比。
- [ ] 失败显示明确状态，不静默重试供应商、不自动换模型；节点不存在时不被任务结果重新创建。
- [ ] 此切片可演示一次文本生成从点击到持久完成，不以仅完成适配器、表结构或静态页面作为交付。

## Implementation context

沿用现有通用模型接入和任务幂等／租约／通知模式，文本正文使用自己的结果契约，不伪装为素材 URL。停止和异常恢复的完整交互由 04 补齐；版本管理由 05 补齐。

## Validation boundary

以公开服务行为和真实画布交互作为验收边界，遵循规格的 Testing Decisions。沿用用户“不运行测试”的要求，本任务清单不授权执行自动测试或真实付费模型联调。类型、lint 与静态检查可用于实施反馈；未执行项必须如实报告。
