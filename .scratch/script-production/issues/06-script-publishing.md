# 06：发布文本与冲突保护

Status: ready-for-agent

**What to build:** 用户主动将选定版本的编辑稿发布为文本节点，并能安全更新原文本或创建新文本；下游只读取发布结果。

**Blocked by:** [05：脚本版本与编辑稿](05-script-versions.md)

## Acceptance criteria

- [ ] 已完成版本可发布编辑稿，首次创建带用途和来源关联的文本节点；停止／中断版本保持发布限制。
- [ ] 再次发布可选择更新原文本或创建新节点，不能悄悄覆盖已有文本。
- [ ] 目标自上次发布后被修改时提示冲突并展示当前内容，默认推荐新建；覆盖必须明确选择。
- [ ] 用户确认覆盖后再次校验目标版本；若期间又变化则重新提示，不能跳过并发保护。
- [ ] 目标已删除时提示创建新文本，不复活旧节点。
- [ ] 发布事务和请求幂等，重复请求不重复建节点，画布历史与无关编辑保持正确。
- [ ] 脚本原稿、编辑稿和流式正文不直接作为下游输出；只有发布文本参与下游输入。
- [ ] 明确更新发布文本后下游显示输入已变化，不自动重新生成；用途标记区分创意、剧本、分镜等。
- [ ] 可以演示生成、手改结尾、发布、修改目标、再次发布冲突，以及发布文本连接第二个脚本节点。

## Implementation context

使用现有画布语义写入、版本检查、历史和内容变化机制，不新增绕过画布保护的直接数据库覆盖路径。

## Validation boundary

以公开服务行为和真实画布交互作为验收边界，遵循规格的 Testing Decisions。沿用用户“不运行测试”的要求，本任务清单不授权执行自动测试或真实付费模型联调。类型、lint 与静态检查可用于实施反馈；未执行项必须如实报告。
