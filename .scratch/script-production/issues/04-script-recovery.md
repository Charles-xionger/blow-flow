# 04：停止、重开与异常恢复

Status: resolved

**What to build:** 用户关闭浏览器后后台继续，重新打开可恢复正文；主动停止或后台异常时保留部分文字，不重复调用供应商。

**Blocked by:** [02：真实脚本后台生成与流式展示](02-script-streaming.md)

## Acceptance criteria

- [x] 浏览器断开不取消已创建的后台任务；重开、重订阅以服务端最新快照恢复正文和状态。
- [x] 点击停止后进入停止处理中；确认停止前禁止同节点再次提交，服务端也实施约束。
- [x] 停止尽力取消供应商流，已保存正文保留并标记未完成；旧流的迟到增量不能改变终态或覆盖新任务。
- [x] 后台进程丢失或租约失效后标记中断，保留已持久化正文；不承诺接续原流，不自动重新调用模型。
- [x] 生成完成与停止竞争时只产生一致终态；界面与查询结果一致。
- [x] 网络重发只恢复原请求身份，不创建第二次付费调用；用户明确重新生成才创建新版本。
- [x] 删除节点后迟到结果不复活节点；已保存任务内容保留。
- [x] 停止和中断结果可查看、编辑但不作为完整结果发布；相关状态通过公开契约供版本与发布功能使用。

## Implementation context

复用现有持久任务和助手恢复经验，但当前完整消息存储不能代替流式正文检查点。区分浏览器断线和后台执行器中断。

## Validation boundary

以公开服务行为和真实画布交互作为验收边界，遵循规格的 Testing Decisions。沿用用户“不运行测试”的要求，本任务清单不授权执行自动测试或真实付费模型联调。类型、lint 与静态检查可用于实施反馈；未执行项必须如实报告。

## Answer

- 服务提供幂等停止接口：排队任务直接停止，运行任务先进入停止处理中，执行器取消后确认；SQLite 状态和租约同时阻止迟到正文及完成写入。
- 执行器以取消信号竞争供应商迭代，即使适配器忽略取消也释放执行器；180 秒总期限防止永久挂起。不重试供应商调用，部分正文始终保留。
- 查询、SSE 快照与新任务提交都会恢复过期租约：运行任务标记中断、停止中任务确认停止，不依赖仍存活的 worker。
- 浏览器卸载仅断开订阅。重开按修订恢复最新快照；匹配持久请求身份的任务自动清除待提交标记，手动恢复仍使用原请求。复制节点的其他节点／画布请求身份不会重放。
- 异步提交、停止和订阅按画布会话及节点存在性隔离，旧页面结果不修改新会话或复活删除节点。独立 activeTask 避免版本选择开放活动任务的再次提交。
- 停止／中断的状态和正文通过公开任务契约保留；编辑与发布资格由任务 05 的版本服务按这些状态控制。
- 验证：`pnpm typecheck`、受影响源码 ESLint、`git diff --check`。遵循用户要求，没有编写或执行自动测试，没有调用付费供应商。类型检查前 pnpm 自动依赖检查报告 tsParticles 构建脚本被忽略，随后 TypeScript 成功；影响范围 ESLint 成功。
