# 第一阶段：脚本创作闭环

Status: needs-info

产品行为已在设计访谈中确认；待确认的是本文的验收边界与任务拆分，不重新开启产品访谈。确认后将规格与任务标记为 ready-for-agent。

## Problem Statement

当前创意描述节点不接收上游参考，一次请求直接生成镜头描述并创建普通文本节点。它无法支持“创意—剧本—分镜文稿”的逐阶段创作，也缺少持久流式输出、独立结果版本、用户编辑稿以及明确发布边界。已有生成过程中部分文字只在内存中，画布自动保存并不能恢复未持久化的流式内容。

用户需要在画布里反复创作、修改和选择文本结果，同时知道本次使用了哪些参考、哪一版文本已供下游使用，并且刷新页面、服务中断或重新生成都不会悄悄覆盖已有作品。

## Solution

以统一的脚本节点取代旧创意描述／分镜生成节点。脚本节点连接参考内容，选择创作任务和模型，使用后台任务流式生成并持久保存文字。完成后可编辑结果、切换历史版本，再明确发布为文本节点；下游只消费已发布的文本。

采用已选定的方案 A：画布中展示结果，节点下方使用参考 LibTV 截图的宽幅深灰圆角控制台。顶部为带编号的参考素材缩略卡，中央为大输入区，左下为模型选择，右下为生成／停止按钮，任务预设和指令编辑使用紧凑入口。生成中使用成熟库提供的粒子效果，不使用普通转圈或虚构百分比。

第一阶段可演示的真实链路：手写创意文本 → 脚本节点生成剧本 → 编辑并发布剧本文本 → 连接另一个脚本节点 → 生成并发布分镜文稿。

## User Stories

1. 作为创作者，我希望从画布中新建脚本节点，以统一处理文本创作任务。
2. 作为创作者，我希望连接已有文本作为参考，以免重复复制创意和剧本。
3. 作为创作者，我希望连接图片作为参考，以向支持视觉的模型表达构图或风格。
4. 作为创作者，我希望看到带编号的参考列表，以确认本次输入。
5. 作为创作者，我希望在要求中引用具体上游节点，以明确描述与素材的对应关系。
6. 作为创作者，我希望所有连入的参考都参与生成，而不是只有被引用的内容参与。
7. 作为创作者，我希望选择自由创作、剧本、分镜或素材提取预设，以获得适合任务的指令。
8. 作为创作者，我希望补充创作要求并修改本节点的任务指令，以保持自己的创作意图。
9. 作为创作者，我希望独立选择语言模型，以比较不同模型的结果。
10. 作为创作者，我希望平台在服务端管理密钥，而不要求我在节点内填写供应商凭据。
11. 作为创作者，我希望生成前发现无效参考或模型能力不匹配，以避免带着错误输入调用模型。
12. 作为创作者，我希望一次生成固定输入，以免生成期间上游修改影响正在进行的请求。
13. 作为创作者，我希望回看每版结果所用的参考、指令、要求和模型，以理解结果来源。
14. 作为创作者，我希望逐步看到模型返回的正文，以及时判断方向。
15. 作为创作者，我希望看到粒子动画和真实状态，以区分等待、输出和异常。
16. 作为创作者，我希望关闭页面后任务继续，并在重新打开时恢复已保存的正文与状态。
17. 作为创作者，我希望主动停止生成，并保留已收到的内容。
18. 作为创作者，我希望同一个节点只运行一个任务，以避免多次输出互相覆盖。
19. 作为创作者，我希望不同脚本节点独立运行，以推进不同段落的创作。
20. 作为创作者，我希望后台异常时保留部分正文，而不自动重试或重复调用模型。
21. 作为创作者，我希望重新生成创建新版本，以保留过去的结果。
22. 作为创作者，我希望模型原稿与编辑稿分开保存，以便修改后仍能回看原始结果。
23. 作为创作者，我希望选择历史版本并编辑，以继续完善曾经满意的方向。
24. 作为创作者，我希望在输入内容较多时展开控制台，以方便编写要求。
25. 作为创作者，我希望主动创建文本节点，以确定哪一份结果供下游使用。
26. 作为创作者，我希望再次发布时可以更新原文本或创建新节点，以保留不同方向。
27. 作为创作者，我希望目标文本被修改后先看到冲突，再决定覆盖还是新建。
28. 作为创作者，我希望脚本草稿变化不影响下游，只有明确发布更新才改变输入。
29. 作为创作者，我希望迁移旧节点时保留提示词、已生成文字、位置和有效连线。
30. 作为创作者，我希望创作助手认识新的脚本节点及发布边界，以避免继续使用旧节点或绕过保护。

## Implementation Decisions

### 范围与既有能力

- 第一阶段交付文本创作闭环。素材提取任务只产生可编辑文本，不创建制作台或图片节点；不显示尚未可用的“更新制作台”按钮。
- 保留通用语言模型调用入口，扩展统一的流式契约；业务层传入模型选择、指令、参考与取消信号，由适配器处理供应商协议。
- 本阶段覆盖已接入的两个 Ark 语言模型，并保持已有 Gemini 文本能力兼容。模型能力显式表达；不依据名称猜测视觉支持。
- 当前完整文本接口不等于持久流式任务。需要新增脚本任务及增量正文存储，复用现有任务身份、幂等请求、租约隔离、通知与恢复模式；不把文字伪装成图片／视频 URL 产物。
- 模型调用与画布页面请求生命周期分离；节点、任务和文本发布通过公开服务契约关联。供应商凭据不进入画布、公开目录或输入快照。

### 输入与任务

- 用户发起时固定已保存的参考内容、参考顺序、创作要求、任务指令、任务预设和模型标识。文本保留展开后的本次内容；图片保留稳定的原始素材身份，不把画布预览图作为生成输入。
- 图片能力和素材可读取性在供应商提交前校验；失败指出具体参考，禁止静默忽略或自动换模型。引用语义沿用既有规则：删引用不等于断线，连入的参考仍参与生成。
- 上游修改不取消当前输入快照，只标记输入已变化；后续新任务采用新内容。
- 创建请求带幂等身份，重复点击、网络重发和页面恢复不得创建第二个供应商调用。
- 每节点最多一个活动任务，由服务端保证；不同节点可独立运行，实际并发仍受平台配置约束。
- 基本状态为等待执行、生成中、停止处理中、已停止、已完成、失败、生成中断。停止处理中不允许再次提交；迟到的旧执行器不能继续写入或覆盖终态。
- 文本增量采用有序追加与持久检查点，页面显示的可恢复正文以服务端已保存内容为准。恢复订阅可取得最新正文与状态，处理重复／乱序通知而不重复文字。
- 关闭浏览器不终止后台任务。后台执行进程丢失后保留已持久化的部分正文，标记中断；不承诺原 token 流续传，不自动重新请求模型。
- 用户停止后尽力取消供应商流，但不承诺供应商已接收的计费会撤销。确认停止后才开放重新生成，旧任务的迟到内容不再生效。
- 已停止／中断内容可查看、编辑，仍带未完成状态；首阶段不以完整结果发布。用户重新生成创建新版本。
- 节点被删除后不因任务结束重新创建节点；完成或部分内容仍归任务保留，遵循现有删除与恢复边界。

### 版本与发布

- 一个生成请求对应一个脚本版本。模型原稿保留原始输出；编辑稿独立保存，初始来自该版本的输出。流式写入不能覆盖已有编辑稿。
- 生成中展示正文；完成后提供编辑与发布。上一版仍可查看。版本列表显示模型、时间和完成状态，并可回看输入来源。
- 首版保留已有版本，不自行清理。简单查看和选用足够，不实现逐字差异比较或版本合并。
- 脚本节点不向下游暴露未发布内容。只有明确发布的文本节点可以被下一阶段脚本或其他生成节点消费。
- 首次发布创建文本节点，附带用途和来源版本关联；后续允许更新原文本或新建。用途至少区分创意、剧本、分镜、素材描述，仍共用文本节点。
- 发布写入复用画布的事务、版本检查、幂等和历史记录；不得用旧整图快照覆盖其他编辑。
- 更新目标前检查其相对上次发布的内容版本。已有人工修改时提示冲突，允许查看当前文本；默认推荐新建，覆盖必须明确选择。
- 明确覆盖仍校验用户看到的目标版本，若目标再次变化则重新提示，不能通过“强制覆盖”绕过并发保护。
- 目标已删除时不能静默复活原节点；提示用户创建新文本。
- 更新已发布文本后，现有下游输入变化提示生效，但不自动重新生成。

### 布局与反馈

- 正式组件按现有节点展示区、节点工具栏、节点控制台分工实现，不直接合入原型代码。
- 单独选中时显示浮动控制台；保持现有拖动时的显隐约定。宽输入区支持展开，处理视口边缘和长文本；不改为默认右侧常驻面板。
- 上方显示参考内容按钮与编号缩略卡；正文要求占主要面积；底部显示模型、任务、指令入口与生成／停止操作。
- 成熟粒子库按需加载，仅活动可见节点运行，限制帧率和粒子数量，遵循减少动态效果偏好。初次等待居中，正文返回后缩到顶部。
- 原型已验证 tsParticles 官方 links 预设可用于交互预览；正式视觉可继续微调，不能替换为普通转圈或自研动画引擎。
- 状态与错误可在节点展示区看见，不以颜色或动画作为唯一信息。不能编造供应商百分比。

### 迁移与助手兼容

- 最终移除旧创意描述／分镜生成类型、入口与旧调用流程，不保留双轨产品入口。
- 旧提示词进入脚本节点，已有生成文字保留为文本节点。尽量保留位置和有效连线；原本依赖旧节点输出的有效连接转向已发布文本，不能改成读取未发布编辑稿。
- 迁移覆盖服务端画布、本地草稿和恢复／导入入口，并且幂等：重复打开或恢复不得重复创建文本节点。
- 迁移不请求模型、不重新生成素材、不重复创建已有文本产物，也不凭空补造缺失文字。
- 助手节点目录、创建和连接能力同步使用新类型和发布服务，沿用已确认的内容所有权与冲突保护。首阶段不新增自动连续执行整条创作链的编排能力。
- 实现过程可在隔离分支上短暂兼容旧结构以分步迁移，但最终交付不保留旧入口或旧执行路径。

## Testing Decisions

用户此前明确要求不运行测试，该要求继续生效。本轮仅写文档；下列是拟定的行为验收边界，不代表已经执行测试，也不授权真实付费模型联调。

- 优先从“脚本任务服务＋发布服务”的公开边界验证，观察任务、正文、版本与画布结果；不针对内部函数拆分或 CSS 类名写镜像测试。
- 借鉴现有持久生成任务、任务通知、助手恢复、画布协议、迁移与浏览器节点交互的验证方式。供应商输出使用可控的流，任务与画布状态使用隔离存储。
- 重点覆盖幂等请求、每节点活动任务唯一、重复增量、断线重新订阅、停止竞争、租约失效、人工编辑保护、发布冲突、节点删除和迁移幂等。
- UI 验收边界为实际画布：控制台布局、参考输入、粒子与正文切换、版本选择、发布和下游输入变化；不要求逐帧断言动画。
- 功能联调时应区分模拟供应商通过与真实平台可用，不用前者声称后者通过。真实平台调用需要可用凭据并控制调用范围。
- 实施期间可进行类型、lint 和静态检查；未经用户改变要求，不运行自动测试。最终报告明确标注未执行的验证与剩余风险。

## Out of Scope

- 制作台弹窗、角色／场景／道具卡片、结构化分镜列表与重新拆解差异合并。
- 本阶段新增图片或视频生成能力、自动素材关联、批量制作及自动连续工作流。
- 音频上传节点、初步观看节点；声音生成和声音库仍为更后续范围。
- 原 token 流断点续传、后台异常自动重试、历史版本自动清理、逐字差异或版本合并。
- 将旧节点永久保留为第二套产品入口。
- 把原型的模拟数据、固定节点位置、结果占位或对比切换器带入生产。
