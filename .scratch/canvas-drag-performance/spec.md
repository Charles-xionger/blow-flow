# 拖动节点不卡顿

Status: ready-for-agent

## Problem Statement

创作者拖动节点时，节点内容被替换成“移动中…”，拖动开始的那一下有明显卡顿。dev 和生产构建都能感到。

## Solution

拖动时节点内容照常显示。按下鼠标不再立即挂载节点工具栏和节点控制台，单击完成后才出现；直接拖动未选中的节点，整个过程都不挂载它们。

## 实测原因

生产构建，50 个节点（文本、文生图、原图、图生图，含节点引用和 2048² 大图），无头 Chromium，同一文生图节点各测 3 次：

| 情况 | 拖动开始主线程 | 长任务 >30ms |
|---|---|---|
| 拖动未选中节点 | 86–97ms | 每次一个 60–71ms |
| 先选中再拖 | 14–30ms | 无 |
| 拖动中（每次移动） | 约 6–7ms | 无 |

按下鼠标时节点被选中，节点外壳挂载节点工具栏和节点控制台（含提示词编辑器）。越过拖动阈值后 `dragging` 为真，又立即卸载它们，同时把内容换成“移动中…”。白挂载一次再卸载，就是这次长任务。

每帧的 store 订阅、autosave 状态写入、`onNodesChange` 的额外工作在生产构建中每帧不到 1ms，不是原因。

## User Stories

1. 作为创作者，我希望拖动节点时仍看到节点内容，这样能看清自己在移动什么。
2. 作为创作者，我希望直接拖动一个未选中的节点时不卡顿，这样整理画布顺手。
3. 作为创作者，我希望单击节点后才出现节点工具栏和节点控制台，这样拖动时它们不闪现。
4. 作为创作者，我希望拖动已选中的节点时，节点工具栏和节点控制台暂时隐藏，松手后原样出现，控制台里未提交的输入不丢。
5. 作为创作者，我希望拖动过程中顶栏的保存状态不跳动，松手后才变为“保存中”。

## Implementation Decisions

- 去掉“移动中…”占位和拖动时的 `content-visibility` 隐藏。
- 节点外壳在按住节点期间不挂载节点工具栏和节点控制台。一次按住若发生了拖动，且此前尚未挂载，则直到节点取消选中前都不挂载；框选等不经按住的单选照常挂载。
- 已挂载后，只要节点仍单独选中就保持挂载；拖动期间用样式隐藏，不卸载。
- autosave 在交互期间（拖动、平移）只记录变更，不写保存状态；交互结束时置为“保存中”并安排保存。
- 不做每帧优化（节点 selector、整表订阅、`onNodesChange` 快速路径），实测收益不足 1ms。

## Testing Decisions

- 浏览器测试：拖动未选中节点的全过程中，节点工具栏和节点控制台从未出现在 DOM 中。不断言长任务：自动化输入的等待会计入长任务，指标不可靠。
- 浏览器测试：拖动已选中节点时两者隐藏但仍在 DOM 中，松手后可见，控制台内输入保留；拖动时节点内容可见、无“移动中”。
- autosave 单元测试：交互期间的变更不改变保存状态，交互结束后变为“保存中”。

## Out of Scope

- 平移、缩放画布的性能。
- MiniMap 每帧重绘（生产构建中不显著）。
- GPU 合成大量图片的开销（无头环境无法复现）。
