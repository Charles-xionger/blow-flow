# Go 迁移切流验收边界

状态：已确认的产品与发布边界；实施和验收尚未完成。

本文记录本地演练、生产切流和正式开放的门槛。各模块的实现细节仍以对应迁移设计及 ADR 为准。平台积分、用户扣费和支付不在范围内，见 [ADR-0018](../adr/0018-do-not-build-platform-credits.md)。

## 本地端到端演练

先在本地跑通同一创作者账户下的完整链路：登录、导入历史项目、读取与保存画布、调用创作助手、确认生成、查看进度和结果。演练要覆盖服务重启、重复请求、失败恢复和回滚。生产环境信息到位后再执行生产切流。

演练所用迁移数据应覆盖项目、文件夹、画布、素材、脚本任务、助手会话与个人技能库，并核对内容、标识、资源归属和访问权限。个人技能库目前仍需迁入 Go 账户边界；不能因为其他资源已经导入就判定迁移完成。

## 创作助手切流门槛

Go 路由接管正式创作助手流量前，现有画布操作、已有节点编辑确认、图片和视频生成、素材引用、技能读取及结果回填都必须通过接口测试和本地演练。画布与生成确认遵循 [ADR-0008](../adr/0008-platform-managed-background-agent.md)、[ADR-0009](../adr/0009-agent-canvas-history-and-conflicts.md) 及 [ADR-0010](../adr/0010-progressively-loaded-creative-skills.md)。

切流时未完成的旧助手任务保留消息和步骤，标记为中断且只读。用户需要发起新任务；旧确认、旧生成请求和旧供应商任务不得被 Go Runner 重新执行或付费提交。

## 生产切流与回滚

生产环境先让内部账号使用 Go 路径，观察并处理问题后再逐步开放给普通用户。每个项目在任一时刻只能有一个权威写入方，不能由 Next.js/SQLite 与 Go/PostgreSQL 同时写入。

回滚演练必须覆盖 Go 已产生新项目或任务的情况：先停止写入，导出并核对切流后的新增数据，再恢复旧入口。不能直接以旧 SQLite 内容覆盖 PostgreSQL 的新增内容。

正式切流前，生成运营后台应能查看生成和脚本任务数量、耗时、失败原因、队列积压、供应商用量与成本，并能定位单个异常任务。供应商用量和成本只用于内部运营。

固定回归案例应覆盖当前支持的图片、视频、脚本和创作助手工具。每个案例除接口响应外，还须核对结果已保存、可在画布查看，以及失败后可安全恢复。重复消息或重试不能造成重复付费提交。

## 面向普通用户开放

本地演练可使用受控创建的创作者账户。面向普通用户开放前，须完成自助注册、邮箱验证、密码找回，以及多实例部署下的验证码和登录防护。

以上门槛是验收条件，不代表对应功能已经交付。具体部署位置、生产数据备份和监控阈值在生产环境确定后写入操作手册。
