# 创作助手首版：自由编排画布与生成工具

Status: ready-for-agent

## Problem Statement

创作用户已有可编辑画布、图片与视频生成能力及持久操作历史，但仍需手动组织节点、整理提示词、配置生成和串联结果。用户希望用自然语言和参考素材表达意图，让创作助手理解当前项目、自由组合工具并快速产出创意，同时保留对实际生成的确认权、停止权和撤销能力。

助手不能被限制成“剧本→分镜→图片→视频”的固定流程，也不能要求用户重复描述参考图中已有的信息。生成及画布修改不能依赖浏览器一直打开，重新进入项目时应能理解已经发生的操作和仍需处理的事项。

## Solution

在当前项目提供侧栏创作助手，以 Pi Agent 为内核，首版接入 Gemini，通过应用内部 MCP 读取画布、理解参考素材、编辑内容、布局和调用已有图片与视频生成能力。剧本和分镜是内置创作技能的示例，不是强制流程。

助手先利用用户对话、参考素材和画布上下文，自主准备创作方案；仅对影响交付物的关键歧义提问。普通画布编辑直接执行并进入历史，图片与视频生成按一批明确操作取得用户确认。用户可以在对话中修改要求、回答问题、停止执行，并通过现有历史撤销画布修改。

任务在后台执行，关闭页面不停止；等待用户的状态持续保存。服务重启后，中断的 Agent 任务由用户继续，已经提交的生成任务自动恢复查询，不重复提交。首版采用同一内容直接覆盖的规则，不建设人工编辑冲突裁决流程。

## User Stories

1. 作为创作用户，我希望在当前项目侧栏表达创作要求，以便跨节点完成创作。
2. 作为创作用户，我希望助手读取整张画布的相关内容和关系，以便利用已有成果。
3. 作为创作用户，我希望引用或提供参考素材，以便无需重新用文字描述所有细节。
4. 作为创作用户，我希望助手先理解参考图中的外观、风格和构图，以便减少重复提问。
5. 作为创作用户，我希望助手只询问影响结果的关键歧义，以便快速进入创作。
6. 作为创作用户，我希望用自由文本回答或修改建议，以便不受固定表单限制。
7. 作为创作用户，我希望助手根据意图自由组合工具，以便直接生成、编辑或组织已有内容。
8. 作为创作用户，我希望助手能生成剧本和拆分分镜，以便快速组织创意。
9. 作为创作用户，我希望不使用这些技能也能完成其他创作要求，以便避免固定流程。
10. 作为创作用户，我希望助手创建和修改节点及连线，以便减少重复操作。
11. 作为创作用户，我希望普通编辑无需逐步确认且可以撤销，以便保持创作速度。
12. 作为创作用户，我希望未明确要求的删除先征求我的意见，以便避免误删已有内容。
13. 作为创作用户，我希望新增内容排在相关节点附近且不挪动已有节点，以便保持画布可辨认。
14. 作为创作用户，我希望明确要求时可以整理画布，以便改善复杂内容的阅读顺序。
15. 作为创作用户，我希望指定选区时只整理该选区，以便保留其余布局。
16. 作为创作用户，我希望查看助手准备生成的内容、参考素材、数量及关键规格，以便决定是否执行。
17. 作为创作用户，我希望一次确认一批明确生成操作，以便不必逐个批准内部工具调用。
18. 作为创作用户，我希望确认前可通过对话修改方案，以便使生成符合创意方向。
19. 作为创作用户，我希望实际提交符合已确认的方案，以便确认不是形式上的提示。
20. 作为创作用户，我希望修改生成要求后尚未提交的受影响任务重新确认，以便避免执行旧方案。
21. 作为创作用户，我希望使用已有图片模型生成或参考素材创作，以便复用项目现有能力。
22. 作为创作用户，我希望使用已有视频模型和其支持的参考素材生成视频，以便连续完成创作。
23. 作为创作用户，我希望助手能等待前一步结果再执行后续步骤，以便自由组合有依赖的工具。
24. 作为创作用户，我希望是否暂停选图由任务意图决定，以便不必每次走固定检查流程。
25. 作为创作用户，我希望后续未批准的生成另行确认，以便控制执行范围。
26. 作为创作用户，我希望选择可用模型且不配置供应商凭据，以便直接使用平台能力。
27. 作为创作用户，我希望运行期间补充消息可以调整当前任务，以便及时纠正方向。
28. 作为创作用户，我希望同一项目不会有多个 Agent 任务同时修改画布，以便保持行为清楚。
29. 作为创作用户，我希望不同项目可以各自执行任务，以便互不阻塞。
30. 作为创作用户，我希望关闭页面后任务继续执行，以便无需一直守着画布。
31. 作为创作用户，我希望重新打开后恢复消息、执行进度和画布结果，以便接续工作。
32. 作为创作用户，我希望等待问题或确认不会超时变成同意，以便保持决定权。
33. 作为创作用户，我希望重新打开后仍能回答、修改或取消待处理事项，以便不丢失交互。
34. 作为创作用户，我希望停止后不再发起后续操作，并取消本轮未提交的生成，以便结束不需要的工作。
35. 作为创作用户，我希望停止时保留已完成内容和已提交任务的结果，以便不丢失已有成果。
36. 作为创作用户，我希望服务重启后可主动继续中断任务，以便恢复时不会悄悄重复执行。
37. 作为创作用户，我希望已提交生成自动恢复查询，以便不重复生成或付费。
38. 作为创作用户，我希望部分生成失败时保留成功结果并明确失败原因，以便决定是否重试。
39. 作为创作用户，我希望重新生成由我确认，助手不自行反复尝试或换模型，以便控制实际调用。
40. 作为创作用户，我希望 Agent 的完整创作步骤形成可撤销批次且内部操作可追溯，以便理解和恢复修改。
41. 作为创作用户，我接受首版 Agent 覆盖同一内容的后续人工修改，并希望能通过历史撤销，以便简化协作交互。
42. 作为创作用户，我希望其他无关编辑不被旧画布快照覆盖，以便保留不相干的工作。
43. 作为创作用户，我希望删除的目标节点不会被 Agent 自动复活，以便删除意图得到保留。
44. 作为创作用户，我希望撤销或重做不会重新调用生成模型，以便历史操作不产生额外生成。
45. 作为平台管理员，我希望统一配置创作助手的平台连接和模型，以便用户无需管理凭据。
46. 作为维护者，我希望内置技能按需加载，以便增加创作能力而不把所有指令塞入每轮上下文。

## Implementation Decisions

- **内核与职责**：采用 Pi Agent，首版使用 Gemini。运行时负责对话和工具编排；应用负责项目状态、步骤记录、批准、画布规则和任务持久化。Pi 的包组合、版本和适配方式需集成验证，不将 SDK 内存状态作为唯一事实来源。
- **模型与平台连接**：管理员统一管理连接及凭据，创作用户选择模型。将助手文本/多模态能力纳入平台模型接入；保留已有图片、视频生成服务及模型能力契约。不扩大为所有旧模型调用路径的全面迁移。
- **MCP 边界**：首版仅供应用内助手使用，不开放外部客户端。工具至少支持读取画布和参考素材、发现模型能力、节点与连线编辑、布局、生成提交与结果查询，以及必要的人机交互。具体工具名称和拆分由实现确定，不固定业务流程。
- **上下文与技能**：参考图先交给模型理解，画布提供结构和相关素材；模型不能可靠判断的创作意图才询问。先提供内置剧本、分镜等技能，先发现再按需读取指令及配套资源；不依赖用户技能上传管理。
- **参数化**：模型输出结构化工具参数；工具入口及应用服务校验必填项、类型、当前模型支持的尺寸、时长、参考类型和素材有效性。参数能力来自已接入模型，不由 Agent 编造。生成复用既有请求去重、输入快照、任务跟踪及产物保存机制。
- **人机交互**：区分需求澄清与生成批准。澄清可用对话和选项；批准针对明确的一批生成操作，展示生成内容、参考素材、数量和关键规格，允许修改或取消。不强制完整参数编辑器，也不强制每个内部步骤单独确认。
- **批准约束**：应用记录批准范围及对应生成要求，执行层检查实际调用是否在该范围内，不能信任 Agent 自报已确认。风格、参考素材、数量等要求改变时，暂停尚未提交的受影响操作并重新确认。已提交任务不视为被撤回。用户补充新要求与普通人工编辑分别处理：前者可能改变批准范围，后者采用同内容覆盖规则；若实际提交参数因此改变，同样不能沿用不匹配的批准。
- **连续执行**：支持生成结果作为后续工具输入。是否停下来挑选结果由任务与用户意图决定，不写死角色图到视频的顺序。批准未覆盖的后续生成需另行确认。
- **画布操作**：用户要求范围内的普通创建、修改、移动可直接执行；删除已有内容须用户明确要求，否则询问。服务端操作复用现有历史语义，不能绕过应用规则直接改原始存储。
- **布局**：Agent 给出布局意图，由确定性代码计算坐标。新增内容仅布局新增节点并在相关节点附近寻找可用位置；用户明确要求整理才移动已有节点，指定选区时仅整理选区。优先评估 elkjs 等成熟方案，未锁定依赖；分组和节点尺寸应纳入布局计算。
- **历史**：一次完整创作步骤形成可撤销批次，内部变更逐条记录；生成批准批次与画布撤销批次是不同概念，不强制一一对应。复用现有持久历史，不建立第二套撤销栈；撤销、重做不重新调用模型。任务进度和等待状态不作为画布内容编辑进入撤销栈。
- **并发编辑**：Agent 对仍存在目标的同一内容可直接覆盖期间的人工修改，并记录历史。不得用旧的整张画布覆盖无关修改。该规则替代原人工冲突裁决方案，但不取消现有保存协议的版本检查，需要在最新项目状态上应用操作。
- **删除与迟到结果**：目标节点已删除时跳过写入并说明原因，不复活节点；已提交产物继续保存在任务记录。现有人工生成任务保持原有过期结果保护，Agent 不获得无条件写回任何节点的权限。
- **后台执行与同步**：复用已有后台生成服务，补足服务端任务与节点关联、产物写回及前端同步。目前生成和产物保存可后台运行，但画布挂接仍由浏览器驱动；必须消除这一依赖，保证关闭页面后后续步骤可获得产物并写入画布。同步必须保留无关本地编辑并遵守上述覆盖范围。
- **运行持久化**：持久保存项目关联、对话消息、Agent 任务、步骤执行记录、工具请求身份与结果、批准及待回答事项、关联生成任务。重复提交、重复继续和响应丢失不能重复应用已确认操作或重复创建生成任务。
- **运行可见性**：用户能区分执行中、等待回答、等待批准、重启后待继续、完成、停止与失败，并查看相关结果或原因。这是外部行为要求，不预设内部枚举或数据库结构。
- **并发范围**：同项目同时仅一个 Agent 任务；运行期间新消息补充或调整当前任务，独立新任务需当前任务完成或停止后开始。不同项目可独立运行，仍遵循已有平台生成并发限制。
- **关页与等待**：关闭页面、断网不停止后台运行。需要用户介入时持久等待，关页或超时不视为同意；重开后能回答、修改、取消。
- **停止**：停止后续规划和工具调用，取消本轮尚未提交供应商的生成任务。已提交任务继续跟踪保存，已完成画布操作保留；停止不是撤销，也不承诺撤回供应商已受理任务。
- **服务重启**：恢复消息、步骤及等待事项，中断的 Agent 任务显示待继续，由用户触发续行；不要求首版任意步骤自动恢复。已提交生成任务自动恢复查询，不以重新生成代替恢复，未回答事项不会自动批准。
- **失败与重试**：一批部分失败保留成功部分，报告原因，重新生成须用户确认；Agent 不自行循环生成或擅自换模型。查询和重新保存已有产物可自动重试；提交结果不明确时沿用待核实语义，不直接再次提交。

## Testing Decisions

- **已确认的验收范围**：真实图片、视频供应商调用和产出效果由用户手动验收，自动化不发起真实付费生成。工具参数、重复提交、历史一致性及运行状态仍做本地验证，不将人工生成验收解释为不测试应用逻辑。
- **主要测试入口**：以项目内 Agent 任务服务的公开行为作为主要集成入口，通过开始任务、补充消息、回答/批准、停止和继续观察持久消息、步骤、画布内容及关联生成任务。使用可控的模型/供应商替代输入，真实执行应用持久化、批准判断和画布操作；不逐个 mock 内部模块，也不测试提示词字面值或模型每次选工具的完全相同顺序。
- **复用现有基础**：沿用现有生成服务公开接口测试中临时 SQLite、可替代网络/产物保存边界、请求身份去重与 worker 恢复的方式；沿用画布历史测试中的真实仓库重开、撤销重做和操作身份检查。新测试围绕跨模块可观察行为组织，不为每个内部函数增加测试接缝。
- **服务层关键场景**：普通编辑写回且可撤销；同内容覆盖保留历史及无关修改；节点已删除时不复活；未批准不生成；批准后仅执行相符范围；修改要求使受影响未提交操作重新等待；重复批准/继续不重复提交；同项目单任务且跨项目隔离；停止与提交竞争不突破停止边界；部分失败保留成功；服务重启恢复等待/待继续状态，已提交任务只恢复查询。
- **后台连续执行**：用可控生成结果验证页面关闭时仍完成保存、画布挂接及后续工具输入；已有任务成功但产物保存失败时只重试保存；不明确提交结果不自动重新生成。
- **浏览器验证**：侧栏引用参考、问题回答、生成确认/修改/取消、新消息调整任务、停止、关页重开、历史撤销重做、项目切换；布局检查节点真实尺寸、选区范围和新增内容不移动已有节点。数据边界尽量留在较快的服务接口测试中。
- **真实集成验收**：人工验证 Gemini 理解参考图、自由选择工具、必要澄清和内置技能使用；用户人工验证实际图片/视频生成、参考素材效果与连续创作。记录实际完成和未完成的人工场景，不以替代服务通过声称真实供应商已验收。
- **实现完成时的检查**：按仓库约定执行类型检查、受影响代码 lint 和完整快速测试；本功能涉及共享画布状态、持久化与同步，应执行完整浏览器回归。真实生成仍由人工单独验收。保持验证期间应用、测试、配置和环境不变，失败后的全量结果与定向复测分别报告。

## Out of Scope

- 对外开放 MCP、外部客户端连接和相应接入管理。
- 创作技能上传、删除、列表管理及上传脚本执行。
- 火山引擎、阿里云等后续助手模型接入，以及所有旧生成提供方的全面迁移。
- 固定的剧本到视频流水线、强制完整需求表、逐个内部工具审批及完整参数编辑器。
- 默认免确认的图片/视频生成模式、自动换模型重试及失败后无限重生成。
- 人工编辑冲突裁决 UI、复杂冲突依赖暂停恢复、多 Agent 同项目并发协作。
- 任意历史版本回滚、历史分支编辑器和第二套撤销栈。
- Agent 任意步骤的全自动服务重启续跑、撤回供应商已提交任务的保证。
- 自动调用真实付费图片/视频接口进行测试，以及以自动化判定创意质量。
- 对模型理解参考素材的准确性或创意产出质量作确定性保证。

## Further Notes

- 本规格依据本次访谈及 ADR-0007 至 ADR-0010；模型接入与素材生成继续遵循 ADR-0001、ADR-0002。ADR-0009 已明确调整为首版同内容直接覆盖，旧的人工冲突裁决约定不再作为首版验收条件。
