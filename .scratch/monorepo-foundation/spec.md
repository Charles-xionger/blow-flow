# Turborepo、Gin 与可验证的迁移基础
Status: ready-for-agent

## 用户决定

- pnpm Workspace + Turborepo 管理整个仓库。
- 后端使用 Go + Gin，数据访问使用 GORM，目标数据库 PostgreSQL。
- 先搭基础设施，现有业务逐步迁移。
- 单元、集成、E2E 与 Langfuse eval 建立测试闭环；接入 Sentry。
- 后台管理、生成内容管理、cost、通知、告警进入后续计划。

## 第一阶段：仓库与验证基础（本次）

已于 2026-11-13 完成，见 [实施与验证记录](implementation-results.md)。
本 spec 的后续阶段仍待实施。

- 迁移现有应用到 apps/web，保留已有未提交改动和真实数据。
- apps/api 提供 Gin 启动、存活/就绪检查、请求 ID、优雅退出。
- PostgreSQL 本地 Compose；GORM 连接；Goose 版本化迁移入口。
- Go 单元/HTTP、真实 PG 集成、进程 E2E、现有画布 Playwright。
- CI 分层运行，收集报告；禁止缓存运行型测试和迁移。
- Langfuse synthetic eval 基线、失败门槛、离线报告、显式发布入口。
- Sentry Web/Gin 错误采集，默认关闭，脱敏测试；不自动创建远端项目。
- 不迁移业务数据、不启用 MQ、不开发管理后台、不进行付费模型评测。

验收：根目录统一命令可运行；测试失败退出非零；真实 PG 测试不能
因缺少配置跳过；真实 Gin 进程可启动/退出；画布保持可用；所有失败
区分基线与本次引入；无真实供应商调用或生产内容外传。

## 第二阶段：PostgreSQL 与第一批 Go 业务

- 盘点 SQLite 表、触发器、JSON 查询、同步事务、租约与领取 SQL。
- 建立 OpenAPI + 事件契约、客户端生成与兼容性检查。
- 先迁移项目/工作空间完整业务边界，随后任务与生成模块。
- 一次性数据迁移、备份、计数/关联/媒体核对、冻结写入与回滚演练。
- TypeScript Agent 继续运行，通过公开接口使用迁移后的业务能力。
- 明确迁移顺序不能拆断确认/授权/入队的原子性。

## 第三阶段：异步执行与可观测性

- 根据任务分发、事件广播和运维需求选择 MQ，记录选型。
- transactional outbox、幂等消费、重试/死信、租约、限流、公平调度。
- 统一 project/task/request/trace 关联；worker heartbeat。
- Sentry 发布与 source map、Langfuse 真实任务 tracing、预算受控的模型
  质量评测；数据集版本化、阈值、人工标注与回归比较。
- 队列与 provider 故障注入、断线恢复、重复消息、未知提交结果验收。

## 第四阶段：管理平台与成本

- apps/admin 独立应用；鉴权、RBAC、审计先于生产数据开放。
- 生产内容检索、来源追踪、审核、保留策略、人工操作与审计。
- 成本账本记录用量、价格快照、币种、估算/结算、退款与异常；
  项目/用户/模型维度汇总和预算。
- 任务中心：队列、失败项、保存重试、定位画布、人工处置。

## 第五阶段：通知、告警与创作功能

- 站内通知、订阅偏好、去重、重试；按需求接邮件/webhook。
- 错误率、积压时长、worker 离线、供应商故障、成本阈值；
  冷却、聚合、升级与恢复通知。
- 生成历史、结果选择、批量执行，再推进局部重跑、模板和素材复用。
- 根据真实工作量确定各阶段 tickets，不用占位页面冒充已交付功能。
