# 03: 原任务进度跟踪与结果交付

**What to build:** Go Worker 跟踪已提交 Krea2 任务的真实进度，在供应商成功后保存图片并交付用户；断线、重启或保存失败后继续处理原任务，不重复付费生成。状态与任务事件可通过 Go API 查询，不改前端。

**Blocked by:** 02: Krea2 提交与跨实例并发控制。

**Status:** ready-for-agent

## Context

遵循 ADR-0002、ADR-0003、ADR-0016 和 ADR-0021。供应商成功与交付成功是不同状态。RunningHub WebSocket 只是进度来源，原供应商任务 ID 的 HTTP 查询是恢复依据；百分比必须由实际 Krea2 工作流事件证明。

## Acceptance criteria

- [ ] 已取得原平台任务 ID 的任务可接收 RunningHub WebSocket 进度；WebSocket 未就绪、断线、Worker 重启或完成事件缺失时，继续查询同一平台任务。
- [ ] 任务查询返回真实阶段和经核实的百分比；无法确认百分比时只返回阶段，不按时间猜测进度。状态变化追加不可变任务事件。
- [ ] 供应商结果经确认后转存项目存储；供应商成功与交付成功分别记录，旧任务的迟到结果不覆盖同一节点的新结果。
- [ ] 保存失败保留供应商结果及任务 ID，重试仅执行保存；平台临时文件失效给出明确失败，不自动重新生成。
- [ ] 查询错误有限退避，等待超时与供应商失败分别表达；继续查询只使用原平台任务 ID。
- [ ] 使用模拟 RunningHub WebSocket／HTTP 和对象存储覆盖断线恢复、重复完成事件、查询超时、保存失败及重试；通过 Go API 验证最终状态和事件。
