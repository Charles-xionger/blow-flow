# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Blow Flow 内部管理员。管理员在独立后台中监控生成业务、排查任务异常、核对供应商成本、处理异常用户账户并审阅管理员操作记录。管理员身份不改变其个人创作资源归属。

普通创作者不是本应用的直接用户；他们在 `apps/web` 中完成创作，且不能进入生成运营后台。

## Product Purpose

生成运营后台为 Blow Flow 的图片与视频生成业务提供独立的内部运营入口，帮助管理员回答三类核心问题：系统产生了多少生成任务、任务为何失败或变慢、不同供应商和模型产生了多少成本。

成功意味着管理员可以基于权威任务事件、成本记录、账户状态和审计记录观察并处理生产问题，同时不绕过用户确认、不篡改历史事实，也不把后台变成另一套用户创作工作台。

## Positioning

后台围绕生成任务从供应商提交、结果保存到用户交付的完整生命周期组织运营数据，明确区分供应商成功、交付成功和用户采用，并把供应商用量、失败成本、成本调整及管理员操作保留为可追溯事实。

它服务内部供应商成本与生产运营，不提供用户余额、积分、扣费、售价或收入功能。

## Operating Context

- `apps/admin` 是独立的 Vite Web 应用，用户制作品台位于 `apps/web`；两者调用同一套 Go API。
- 管理员以密码和一次性图片验证码登录。Go API 签发 15 分钟 JWT，并在每次受保护请求中检查角色和账户状态。
- 禁用用户等敏感操作要求登录时间不超过 10 分钟，并写入审计记录。
- 主要模块为总览、生成任务、供应商成本、用户账户和审计记录。
- 当前用户账户与审计页面已接入真实 Go API；生成任务与供应商成本等待各自领域的权威接口完成迁移。
- 数据以 UTC 存储，并按管理员选择的时区展示；总览和队列状态以一分钟内更新为首版目标。

## Capabilities and Constraints

- 后台只能通过 Go API 操作，不能直接访问或修改业务数据库。
- 总览用于观察任务量、成功率、阶段耗时、队列状态和供应商成本。
- 任务模块用于查询任务、查看不可变状态时间线、错误、供应商任务 ID 和结果保存状态。
- 成本模块区分供应商原始用量、预计供应商成本、实际供应商成本、已对账供应商成本、失败成本和成本调整。
- 用户模块支持查看账户状态和禁用异常用户；禁用会立即撤销会话并阻止新的受保护操作。
- 审计模块记录管理员登录、敏感内容访问、任务操作和用户状态变更。
- 管理员可以继续查询已有供应商任务、重试保存已有结果、取消尚未提交供应商的排队任务，以及禁用异常用户。
- 管理员不能未经用户重新确认提交新的付费生成、修改原始输入后沿用旧任务、删除任务事件或成本记录，也不能直接把失败任务改为成功。
- 任务列表默认只显示元数据；查看完整 Prompt 或素材必须记录访问审计，素材使用短时访问地址。
- 日志和错误信息必须脱敏，任何界面都不能展示供应商密钥。
- 平台只包含个人用户账户，首版不建设组织或团队。
- 公开注册、密码找回、任务和成本权威接口、运营告警以及完整生成安全闭环仍按已确认实施顺序推进；界面不能把待接入能力表现为已经可用。

## Brand Commitments

- 产品名称为 **Blow Flow**，后台名称为 **生成运营后台**。
- 界面语言以简体中文为主，文案应直接、克制、可操作，并准确区分任务、成本、交付和账户领域术语。
- 后台与用户创作画布是两个独立入口；不能把生成运营后台称为用户工作台。

## Product Principles

1. **权威事实优先。** 指标来自任务事件和成本记录；缺失数据明确显示为待确认或待接入，不能伪造为零或成功。
2. **可追溯而非可篡改。** 任务事件、成本调整和管理员操作保留历史，后台操作不能覆盖原始事实。
3. **运营处理不绕过用户授权。** 管理员可以恢复查询和结果保存，但新的付费生成仍需用户重新确认。
4. **最小暴露敏感内容。** 默认展示元数据，敏感内容按需访问、短时授权并留下审计。
5. **清晰区分业务口径。** 供应商成功、交付成功、用户采用以及各类供应商成本始终分别表达。
